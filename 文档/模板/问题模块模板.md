# 问题页提纲

用于 `知识库/` 下一个具体问题的持续技术文章。模块名复用已有命名；同一问题优先合并。下面是字段/写作示例，不是真实论文或知识；所有占位符必须替换，引用来自已登记且实际阅读的论文。字段定义见 [SCHEMA](../../SCHEMA.md)。

```yaml
---
id: "{{PROBLEM_ID}}"
title: "{{PROBLEM_TITLE}}"
type: "problem"
status: "reviewed"
updated: "{{DATE}}"
summary: "{{ONE_SENTENCE_PROBLEM_AND_APPROACH}}"
aliases: ["{{COMMON_ALIAS}}"]
sources: {"{{SOURCE_ID}}": "{{FULL_SOURCE_FINGERPRINT}}"}
related: []
module: "{{EXISTING_MODULE_NAME}}"
solutions: [{"name": "{{SOLUTION_NAME}}", "idea": "{{ONE_SENTENCE_MECHANISM}}", "papers": ["{{SOURCE_ID}}"]}]
---
```

```markdown
# {{PROBLEM_TITLE}}

{{问题的直观定义与关键困难，概括主要解决思路；让读者先建立整体认识。}}

## {{问题定义或具体困难}}

{{输入、目标、约束与必要符号；一个例子说明为什么常规做法不足。}}

## {{方案一的技术名称}}

{{核心机制、必要公式/例子、训练推理和代价；公式与符号在本页说明完整，深入推导链接论文 notes 的对应小节。原文出处使用已核实的固定版本 PDF 页码或 HTML 锚点，不把摘要页当作公式链接。}}

## {{方案二的技术名称}}

{{有实际读过的第二种方案再写，解释它解决同一困难的另一条路径；单方案时省略。}}

## {{机制差异与选用条件}}

{{围绕核心假设、监督/数据要求、训练与推理、成本及证据横向比较，解释共同点、具体改了哪一步、何时选用；不同评估协议的数字不直接排名。单方案时可改为适用边界。}}
```

不放来源处理进度、任务历史或模板说明；不留空节、空比较表。不同方案需要时重复相应技术小节；论文链接随论述自然出现，目录从 solutions 自动生成。同一解法的多篇论文合在一个 solution，一篇论文可关联多个问题；新增论文先合并旧页，保留旧证据的条件。仅依据本篇描述的基线/消融时说明来源范围，不冒充独立精读其他论文。没有可复用的独立方法正文时无需额外建 method 页；已有时可在 solution 增加 `method` ID。尚无解法的开放问题使用 `question`，不伪造 problem 条目。
