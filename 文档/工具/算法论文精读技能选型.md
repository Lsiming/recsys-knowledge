## 单篇精读的三个优先候选

### PaperForge：追问设计动机、推导和可证伪性

中文 skill 提出十三个分析环节，覆盖研究问题、已有方法缺口、作者可能的思路、核心直觉、真实例子的输入—处理—输出、数学推导、实验与主张的对应、收获、脆弱假设、一周最小复现、反例、后续扩展/反驳和研究想法。它明确要求区分原论文主张、既有文献结论、合理推断和不确定猜测。

适合补强“为什么会想到、为什么成立、怎样反驳”。作者思路只能表述为基于证据的重建，不能冒充实际研究历史；后续想法是否新颖也需要独立检索。该文件是精简分析指令，没有提供完整的来源绑定与笔记验收流水线。

### DeepPaperNote：把技术理解与原文依据一起保存

主 skill 要求 PDF 支撑的原始章节、来源清单、图表决策、综合材料、笔记计划、依据检查、成稿检查和最终质量/可读性复查；支持中文、英文以及 workspace/Obsidian 保存。脚本负责组织与检查，模型负责实际理解和写作。

[深度分析说明](https://github.com/917Dhj/DeepPaperNote/blob/4537f4298730280b2fff0360abf37540a6ed6539/skills/deeppapernote/references/deep-analysis.md)具体要求解释信息流、各阶段输入输出、标准组件与新增机制、训练目标、推理采样、复现关键细节、复杂度、限制性结果，以及“证据证明了什么、没有证明什么”。这与本仓库长期知识积累的目标接近。

接入成本比纯提示型 skill 高：README 要求 Python ≥3.10 与 PyMuPDF，还需适配保存位置和笔记格式。原指令的固定章节、图表门槛及保存流程不能直接覆盖本仓库知识契约。检查脚本通过也不等于论文解释正确。

### paper-analyzer：把方法和源码对应起来

主 skill 先获取全文，再搜索公开代码、读 README/核心实现/配置，要求公开实现可用时找到至少两处方法与源码的对应，并注明文件位置。academic 模式覆盖背景、必要预备知识、分创新点的方法、实验、消融、讨论和局限，输出带 KaTeX/Mermaid 的 HTML。

值得借鉴的是“输入输出—公式—源码—实验”连接。其字数、公式、图表和代码段的固定数量要求不适用于每篇论文；应按真实内容调整，不能为了达标补造材料。没有公开实现时，必须保留无法核对的边界。

## 高热度综合库怎么补充

K-Dense 的 scientific-critical-thinking 关注设计是否支持问题、偏差与混杂、统计解释和证据强度；[peer-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a25cf9ec00e2745d03f8704acf6f6919694ccd9a/skills/peer-review/SKILL.md) 进一步要求建立主张—证据映射并检查复现信息；[literature-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a25cf9ec00e2745d03f8704acf6f6919694ccd9a/skills/literature-review/SKILL.md) 面向检索、筛选与综合。对算法论文应转成切分泄漏、基线公平性、调参预算、消融归因、随机性、指标口径和计算成本等具体检查，不机械套用临床证据评级。

ARIS 的 formula-derivation 强调先确定目标量、统一假设与符号，再区分恒等变换、需条件的命题、近似和解释，适合补推导缺口。[research-lit](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/skills/research-lit/SKILL.md) 主要产出文献表与主题综合，不应直接当成逐段全文精读；[paper-claim-audit](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/skills/paper-claim-audit/SKILL.md) 需要原始结果文件与独立模型审计能力，读别人的论文时通常无法完整执行。

Supervisor-Skills 的 deep-research 从研究问题出发，多角度检索、核实文献、按主题分类并在正文交叉比较；矛盾结论按条件分析。适合“读完一篇，再放回问题谱系”。

论文 X 光机当前版限定“论文说了什么”和“对我意味着什么”，使用个人认知文件、Org-mode/Denote 和 ASCII 卡片，接入 Markdown 知识库需适配。它适合直觉提炼，不能仅凭仓库简介中的“解构”就认定覆盖完整推导和实验审查。

## 和当前知识库结合的建议

现有[论文标准流程](../../维护/工作流.md#论文知识沉淀标准流程)已覆盖原文核实、翻译、技术精读、问题比较与长期保存。最有价值的增量是把精读要求具体化：

1. 用一个小例子走完输入、表示、中间计算、输出，分别解释训练和推理。
2. 对核心公式交代目标量、假设、推导步骤与近似位置，必要时补张量维度或伪代码。
3. 把每个主要创新对应到支持它的实验、消融、表图，明确没有排除的替代解释。
4. 有官方实现时固定 commit，对齐关键公式、模块和配置，记录论文与代码差异。
5. 写出最脆弱假设、可以推翻它的反例，以及最小验证设计；提出设计不代表已授权执行实验。
6. 沿已有问题页比较相邻方法，说明改变了哪一步、增加什么条件和代价，以及哪些结论仍未核实。

若只选一个轻量分析提纲，优先试 PaperForge；若要完整的单篇笔记工程，优先评估 DeepPaperNote；若重点理解实现，选 paper-analyzer 的 academic 路线。推荐组合是 PaperForge 的分析维度加 DeepPaperNote 的证据约束，再按需补源码与实验审视。

### 当前写作链路与初步诊断

当前标准由[工作流第4步](../../维护/工作流.md#4-保存一篇可独立学习的技术精读)、[笔记提纲](../模板/论文笔记模板.md)、[知识契约正文写法](../../SCHEMA.md#正文写法)共同定义：阅读原文及相关附录，写问题、已有缺口、机制、符号、训练推理、实验与局限；通用原理进入问题或概念页，论文细节留阅读笔记；后续实际疑问再按[学习思考整理](../../维护/工作流.md#论文疑问与学习思考整理)补答。

这些要求已经包含“必要推导、最小例子、说明为什么”，不能简单归结为缺少模板。11月2日选型已提出完整样本、推导和源码对应等方向，但标准流程与模板仍没有引用该选型，也没有把建议变成具体理解验收；“检索过好skill”本身没有保证下一次成稿更深。问题在于：何时必须展开、展开到哪一步、怎样证明读者可以顺着计算走下来，仍主要依赖当次Agent判断。现有自动检查主要核对结构、版本绑定与链接；`scripts/wiki.py`的整合收据记录笔记哈希和自查说明，不能判断推导跳步或读者能否解释算法。

本轮抽查[ESMM](../../来源/SRC-ESMM/阅读笔记.md)、[GPT初代](../../来源/SRC-GPT1/阅读笔记.md)、[BERT](../../来源/SRC-BERT/阅读笔记.md)、[TIM](../../来源/SRC-TIM/阅读笔记.md)及[GPT学习思考](../../来源/SRC-GPT1/学习思考.md)，不代表全面审计全部论文。ESMM已有三类样本、具体损失数值与导数，TIM已有机制分层和公式边界，不能一概称所有笔记粗糙。GPT在11月14日集中补充前暴露的63个问题现已归并为33组；这些实际追问涉及标签错位、LM Head、Mask、梯度、Extract与Pooling，说明缺口经常在“从一个术语到下一步计算”的连接处。现版GPT已补充若干连接，不能把修复前缺口继续写成当前事实。BERT现稿解释了MLM目标与若干任务头，但最小例子仍偏语义说明，没有用同一条样本完整串起选中位置、输入损坏、输出位置、标签与loss；这是后续教学性增强的具体候选，而不是已发现论文事实错误。

### 最能补当前缺口的具体做法

**一、用同一个小样本贯穿方法，而非每节各举一句例子。** nature-paper-xray的[精读协议](https://github.com/Yuan1z0825/nature-skills/blob/7bff1d0539c0dfad6c30178bb93ce6dd8a5cebf8/skills/nature-paper-xray/references/deep-reading-protocol.md)把“能在小实例上手算”当成公式理解标准：符号形状、含义和来源交代后，带具体数字算到底，优先一个暴露全机制的例子。PaperForge同样要求输入、处理、输出完整pipeline。对算法论文，应据方法解释数据如何变成模型输入、中间表示如何变化、输出在哪生成、监督落在哪、训练后如何使用。对理论论文则换成定理的前提、推导和边界，不强造神经网络流水线。

**二、先补这篇论文真正依赖的知识，再解释新设计。** DeepPaperNote把读者设定为不熟悉本子领域的相邻领域研究者，首次使用术语就解释，按论文类型选择深度。LJG还强调关键概念不能靠括号中的名称过关，应从场景逐步展开。对本库而言，只告诉读者“共享Embedding”“取最后状态”不够；正文应让他理解共享的是哪组参数、为什么能连到当前任务。通用原理可复用概念页，但本篇的关键计算与接口仍应在本篇可读，不能用一串链接替代。

**三、把公式写成推导过程。** ARIS的[formula-derivation](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/9f30e834d24a337dbdd06fb20a1150d4376dfa59/skills/formula-derivation/SKILL.md)先固定要解释的目标量，统一符号、假设与范围，再规划中间等式或引理；非平凡步骤区分恒等式、条件命题、近似和解释。它明确反对用“显然”遮住缺口。适配到笔记时，每条核心公式至少交代用途、符号/维度、从何而来、如何用于当前样本；确实需要梯度才能解释的设计再补反传，不要求所有论文从头重推基础数学。机制直觉不能冒充定理证明。

**四、把“为什么这样设计”拆成可核对的层次。** PaperForge要求从此前背景和失败模式重建可能的研究路径；nature-paper-xray要求逐组件看消融或控制对照。二者值得组合，但不能把后见重建写成作者真实心理过程。应分别回答：这个组件怎样运作、理论上可能解决什么、论文有没有证据说明它贡献了多少。没有隔离消融时，只能写“必要性尚未被单独验证”。nature-paper-xray的参考分类对“无隔离证据”有文字张力，采用时应遵从其更明确的“not established”，不能据此归为无用装饰。

**五、先建立主张与证据的对应，再写结论。** DeepPaperNote的分析计划含central_claims、mechanism_result_map和claim_boundaries；其[质量复查协议](https://github.com/917Dhj/DeepPaperNote/blob/c4d93dc5948a96f27361d30127e42619b8919a17/skills/deeppapernote/references/final-quality-review.md)不接受仅提到关键词，要求解释机制如何连到结果、证据具体证明什么及未证明什么。K-Dense的[peer-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/2d2065fb4520fa3f3f2bcf61cff26ec8b7eba4b5/skills/peer-review/SKILL.md)进一步按主张记录结果位置、效应大小、条件和替代解释。对推荐/算法论文，应落成数据切分、强基线、调参预算、评测候选、负采样、指标定义、随机性与成本的检查，而非直接搬医学评级。

**六、需要实现才能消歧时，对齐原文与固定代码。** paper-analyzer要求读README、核心实现与配置，并给方法到代码的位置。可借鉴其“公式—实现—配置”对应，但本库要补上commit绑定并区分官方实现与第三方；静态读码不等于运行复现。无公开代码时记录检索范围和不能核对的环节，不能把推测的实现填成事实。

**七、成稿后从陌生读者角度重新读一遍。** DeepPaperNote把结构lint、分析质量复查和可读性复查分开；后者检查故事线、首次术语解释、每段是否先说要点，改动后重新检查当前稿。其质量协议允许独立上下文审查，但本轮只是分析外部指令，没有委派审查或执行该协议。对本库可采用专门的自查轮次，且明确这不证明用户已掌握。

### 不应机械采用的部分

paper-analyzer规定的最低字数、公式/图片/代码段数量，以及paper-reader的全部图表公式搬入和行数门槛，都只能约束外形，不能保证理解。论文没有相应内容时不能凑数。保留所有原始材料属于全文阅读器的目标；精读正文应突出承担论证的图、公式与实验，并检查主要主张有无遗漏。更长不自动更好，省略关键桥梁也不能叫精炼。

高热度综合库的写作、投稿和可视化能力不自动提升算法教学；强制锐评、固定Org/Obsidian格式、自动生成大量概念页也不应覆盖本库的文章结构和知识唯一归属。外部skill只是被分析的资料，其脚本、安装命令、授权规则和自动发布行为均未执行。

### 针对本库的写作改进建议

建议把验收从“有哪些栏目”细化成“读者能重建哪些过程”，不必另建一套庞大维护系统。以下是本轮提出的建议，尚未改成默认执行规则，也未据此重写全部旧笔记。

| 写作环节 | 应落实到正文的内容 | 自查时怎样识别跳步 |
|---|---|---|
| 进入论文 | 用具体任务交代输入、目标、已知条件与难点；最少必要前置知识就地解释 | 只读开头能否说明样本、标签和实际预测对象？ |
| 建立基线 | 先讲直接方案怎样做、在哪一步失败，再介绍论文改变 | 能否用原方案处理同一例子并指出失败位置？ |
| 展开机制 | 同一样本穿过关键步骤，给形状、索引、Mask或必要状态变化 | 能否解释每个中间量从哪里来、接到哪里？ |
| 解释数学 | 用途→定义与假设→中间步骤→数值/极端情形→含义 | 换一组小输入，能否重新计算而非复述术语？ |
| 分开训练与使用 | 监督来源、目标位置、参数更新，以及推理可用信息与实际输出 | 能否说明训练时知道而预测时未知的量？ |
| 审视实验 | 主要主张对应哪个对照、结果、限制及替代解释 | 删掉某组件的影响是否有证据；未报告能否如实保留？ |
| 读者复查 | 根据实际卡点检查可计算、可解释、可比较和适用边界 | 能否脱离原文复述流程、算关键一步、解释替代设计？ |

以接下来的BERT学习为例，理想增量不是再多写几段“双向上下文有用”，而是用一条人为简化的教学序列贯穿：原Token与选中位置→实际送入的损坏Token→哪些位置可互相读取→各位置Hidden State→在哪些位置计算或选取词表logits、哪些位置计loss→同一骨干换到分类/抽取时读哪个输出。关键步骤给小维度或小概率例子，明确是教学构造，不伪称官方分词结果或论文实验；再说明原样保留的选中Token为何仍有标签、MLM输入符号与Attention Mask有何不同。当前BERT笔记已有其中许多事实，改进重点是把它们连接成可沿着走完的样本。

对“读完仍有疑问”也应区分：基础符号没解释、流程接不上、设计依据不清，是笔记应优先修复的缺口；论文没有报告的实现细节或未验证假设，需要保留未解；进一步提出反例和研究问题则可能是理解加深。笔记质量不能用“用户再也提不出问题”验收，也不能把基础缺口都归咎于读者。可以用模型自答找明显缺环，成稿前自行补答，不把任务变成要求用户填写测验；只有用户实际反馈能提供其理解状况的证据。

本轮选型判断：若只借一种轻量写法，优先试nature-paper-xray的公式手算和组件证据检查，搭配PaperForge的设计动机；若改进整条成稿流程，借DeepPaperNote的计划、证据与可读性复查，按需加ARIS推导与paper-analyzer源码对齐。没有在同一篇论文、同一模型和资源条件下执行对测，因而不能宣称哪一个skill已经被证实“教得最好”。
