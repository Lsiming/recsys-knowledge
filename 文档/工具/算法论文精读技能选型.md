## 单篇精读的三个优先候选

### PaperForge：追问设计动机、推导和可证伪性

中文 skill 提出十三个分析环节，覆盖研究问题、已有方法缺口、作者可能的思路、核心直觉、真实例子的输入—处理—输出、数学推导、实验与主张的对应、收获、脆弱假设、一周最小复现、反例、后续扩展/反驳和研究想法。它明确要求区分原论文主张、既有文献结论、合理推断和不确定猜测。

适合补强“为什么会想到、为什么成立、怎样反驳”。作者思路只能表述为基于证据的重建，不能冒充实际研究历史；后续想法是否新颖也需要独立检索。该文件是精简分析指令，没有提供完整的来源绑定与笔记验收流水线。

### DeepPaperNote：把技术理解与原文依据一起保存

主 skill 要求 PDF 支撑的原始章节、来源清单、图表决策、综合材料、笔记计划、依据检查、成稿检查和最终质量/可读性复查；支持中文、英文以及 workspace/Obsidian 保存。脚本负责组织与检查，模型负责实际理解和写作。

[深度分析说明](https://github.com/917Dhj/DeepPaperNote/blob/4537f4298730280b2fff0360abf37540a6ed6539/skills/deeppapernote/references/deep-analysis.md)具体要求解释信息流、各阶段输入输出、标准组件与新增机制、训练目标、推理采样、复现关键细节、复杂度、限制性结果，以及“证据证明了什么、没有证明什么”。这与本仓库长期知识积累的目标接近。

接入成本比纯提示型 skill 高：README 要求 Python ≥3.10 与 PyMuPDF，还需适配保存位置和笔记格式。原指令的固定章节、图表门槛及保存流程不能直接覆盖本仓库知识契约。检查脚本通过也不等于论文解释正确。

### paper-analyzer：把方法和源码对应起来

主 skill 先获取全文，再搜索公开代码、读 README/核心实现/配置，要求公开实现可用时找到至少两处方法与源码的对应，并注明文件位置。academic 模式覆盖背景、必要预备知识、分创新点的方法、实验、消融、讨论和局限，输出带 KaTeX/Mermaid 的 HTML。

值得借鉴的是“输入输出—公式—源码—实验”连接。其字数、公式、图表和代码段的固定数量要求不适用于每篇论文；应按真实内容调整，不能为了达标补造材料。没有公开实现时，必须保留无法核对的边界。

## 高热度综合库怎么补充

K-Dense 的 scientific-critical-thinking 关注设计是否支持问题、偏差与混杂、统计解释和证据强度；[peer-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a25cf9ec00e2745d03f8704acf6f6919694ccd9a/skills/peer-review/SKILL.md) 进一步要求建立主张—证据映射并检查复现信息；[literature-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a25cf9ec00e2745d03f8704acf6f6919694ccd9a/skills/literature-review/SKILL.md) 面向检索、筛选与综合。对算法论文应转成切分泄漏、基线公平性、调参预算、消融归因、随机性、指标口径和计算成本等具体检查，不机械套用临床证据评级。

ARIS 的 formula-derivation 强调先确定目标量、统一假设与符号，再区分恒等变换、需条件的命题、近似和解释，适合补推导缺口。[research-lit](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/skills/research-lit/SKILL.md) 主要产出文献表与主题综合，不应直接当成逐段全文精读；[paper-claim-audit](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep/blob/c485faa59a68e51c6575dea67ca57abc7a6a2b9c/skills/paper-claim-audit/SKILL.md) 需要原始结果文件与独立模型审计能力，读别人的论文时通常无法完整执行。

Supervisor-Skills 的 deep-research 从研究问题出发，多角度检索、核实文献、按主题分类并在正文交叉比较；矛盾结论按条件分析。适合“读完一篇，再放回问题谱系”。

论文 X 光机当前版限定“论文说了什么”和“对我意味着什么”，使用个人认知文件、Org-mode/Denote 和 ASCII 卡片，接入 Markdown 知识库需适配。它适合直觉提炼，不能仅凭仓库简介中的“解构”就认定覆盖完整推导和实验审查。

## 和当前知识库结合的建议

现有[论文标准流程](../../维护/工作流.md#论文知识沉淀标准流程)已覆盖原文核实、翻译、技术精读、问题比较与长期保存。最有价值的增量是把精读要求具体化：

1. 用一个小例子走完输入、表示、中间计算、输出，分别解释训练和推理。
2. 对核心公式交代目标量、假设、推导步骤与近似位置，必要时补张量维度或伪代码。
3. 把每个主要创新对应到支持它的实验、消融、表图，明确没有排除的替代解释。
4. 有官方实现时固定 commit，对齐关键公式、模块和配置，记录论文与代码差异。
5. 写出最脆弱假设、可以推翻它的反例，以及最小验证设计；提出设计不代表已授权执行实验。
6. 沿已有问题页比较相邻方法，说明改变了哪一步、增加什么条件和代价，以及哪些结论仍未核实。

若只选一个轻量分析提纲，优先试 PaperForge；若要完整的单篇笔记工程，优先评估 DeepPaperNote；若重点理解实现，选 paper-analyzer 的 academic 路线。推荐组合是 PaperForge 的分析维度加 DeepPaperNote 的证据约束，再按需补源码与实验审视。
