# 研究工作流

执行入口见 [AGENTS](../../AGENTS.md)，任务组织见 [协作规范](上下文与多会话协作.md)。流程按交付需要使用，不要求每次问答都填写完整模板。

## 1. 确定问题与资料范围

用户提供论文 URL/ID/PDF/题名，即按 [默认论文流程](../../维护/工作流.md) 完成翻译、精读笔记和问题方案归纳；无需另外确认 R001、目录或阅读深度。已有资料先检索并增量补齐。用户只要其中一步时遵从；题名不能唯一定位时才澄清身份。

开放调研先明确本轮问题与场景，例如“某序列模型如何减少在线推理成本”“生成式推荐与现有召回相比改变了什么”。场景不明时先做可独立推进的原理解读，再澄清依赖场景的部分。常规论文无需任务编号，恢复/并发/实验另查有效任务。

“前沿/最新”记录检索截至日期、来源和检索范围；没有全面检索时写“本次检索覆盖”，不宣称完整榜单。时间以用户环境日期为准；每次检索记录自身日期，不沿用初始化日期。

## 2. 阅读与证据

优先原论文、官方仓库、作者/机构技术报告。记录题目、作者/机构、年份、URL、arXiv/DOI 或其他标识、版本及阅读深度；需要时注明代码 commit。无法访问全文写明限制，不用摘要补造实验细节。

笔记以技术文章解释问题、缺口、具体解法和证据。正文自然区分原文报告、本仓库复现、分析推断、待验证假设，不反复粘贴标签或维护声明。关键结论就近定位章节/图表，比较数值带上数据、基准、指标定义、单位与设置；二手来源标明身份并尽量追到原始资料。

单篇解读进入 `来源/<ID>/阅读笔记.md`；在 `知识库/` 对应问题页讲可复用机制和多方案异同，按模块聚类并相互链接。[论文提纲](../模板/论文笔记模板.md)、[问题页提纲](../模板/问题模块模板.md) 仅作提示；字段以 [知识契约](../../SCHEMA.md) 为准。原件在 `.local/sources/` 冻结，许可确认后的正式 Markdown 译文放 `译文/<ID>/中文译文.md`，PDF、工作版/未授权译文与工程放 `.local/papers/<ID>/translation/`；笔记文末简记实际范围、格式、位置和未完成项。完整译文不复制进精读笔记。

## 3. 方法比较与业务映射

比较至少说明输入与预测目标、架构变化、训练目标、推理方式、数据条件、评估基准、计算成本和限制。不同数据或协议下的论文数字不直接作优劣排名。

学习按“模块 → 问题 → 解法 → 论文”组织。同一问题已有方案时解释机制、条件与代价的差异；没有已读对照时先讲清单方案，不填空表，也不将论文 Related Work 中的转述冒充已精读比较。

业务适用性按“可以借鉴什么 → 需要哪些条件 → 证据缺口 → 最小验证”写。CTR/CVR、排序、价值回归、因果效应和实际交易收益各有目标；离线指标改善不能直接承诺业务收益。

## 4. 最小复现与实验

使用 [实验记录模板](../模板/实验记录模板.md)，先声明研究问题、基准、唯一主要变更、数据切分、指标、资源和停止条件。纯探索可明确标为描述性，不用于晋级，不凭结果回填预设阈值。

实验 ID 唯一；记录 Git 基线和实际 dirty 范围（有条件时保存补丁/哈希）、依赖版本、配置、数据版本/来源、seed、命令、环境和输出路径。重试保留父 run ID 与尝试号，不覆盖旧结果。

数据切分按任务考虑用户/物品重复、时间穿越、标签成熟与特征泄漏。训练/调参/最终测试用途明确；多 seed 不能单独证明显著性。只有验证过的数值才写“本仓库复现”。

真实样本、权重与原始日志留忽略目录；小型非敏感汇总和图表可入专题 `assets/`。Git 记录代码、配置与运行说明，外部或本地产物需在报告注明位置与可复现限制。

目前没有默认模型环境或运行入口；首次实验明确自己的依赖和命令，不为文档项目提前安装训练框架。

## 5. 验证与结论回写

| 修改类型 | 适用验证 |
|---|---|
| 文档、交接、索引 | 来源/当前状态一致性，`python3 scripts/check_context.py`、`python3 scripts/wiki.py lint`，`git diff --check`；暂存后 `git diff --cached --check` |
| 配置/代码 | 上述检查，加对应格式/语法与必要语义/smoke 检查；只跑与变化相关的验证 |
| 真实实验 | 上述检查，加实际命令、成功/失败、输出身份、关键指标和限制核验 |

只记录实际执行的检查；链接存在不代表来源正确，脚本通过不代表科研结论通过。未具备运行条件时交付已完成的分析和明确缺口，不伪造复现结果。

完成后同步知识/来源索引与 log，真实实验更新实验索引；有任务时更新独立交接和有效队列。领域知识进入 wiki 并链接证据，只有项目级稳定事实才进入 MEMORY。按本地 Git 约定提交，汇报真实交付与未覆盖范围。
