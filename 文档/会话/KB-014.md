# KB-014：修复知识库检查工作流的Python矩阵

2026-11-08，Transformer知识更新提交后触发GitHub Actions失败通知。run `42473827178`和`42474037318`日志均显示Hosted runner为Ubuntu 26.04，`actions/setup-python@v5`报“The version '3.9' with architecture 'x64' was not found for Ubuntu 26.04.”Python 3.9 job在步骤初始化阶段失败；matrix默认`fail-fast: true`又取消了Python 3.13 job，知识检查命令尚未开始执行。此前成功run `41456875217`发生于11月2日，当时`ubuntu-latest`仍提供兼容镜像。

修复：将`.github/workflows/checks.yml`的runner固定为`ubuntu-24.04`，继续覆盖Python 3.9和3.13；设置`fail-fast: false`，让矩阵结果分别完成并可诊断。修改后运行工作流中的索引、lint、译文/PDF目录、下载列表、上下文链接、完整历史和公开性检查、单元测试及提交空白检查；提交后检查两个GitHub Actions任务均成功。

通知中的直接失败发生在Python安装阶段，知识或工具测试尚未执行。本地补跑另发现8个新登记paper来源未进入正式Markdown译文目录，导致translations.py check失败；已为BPE、FlashAttention、LayerNorm、Pre-LN、RMSNorm、RoFormer、SentencePiece和Weight Tying补齐local-only登记并重建目录，明确仅定向核对原文、未制作全文译文、未核实全文分发许可。没有新增公开译文或PDF。

Python 3.9已停止上游安全维护；本次固定镜像用于维持仓库当前声明的Python 3.9+兼容检查，后续提高最低版本时需同步README和测试矩阵。

本地Python 3.9.6已通过完整工作流命令：知识/来源索引、lint（保留既有3条warning）、71篇论文译文目录、63篇PDF目录、下载列表、上下文链接、完整公开历史隐私扫描及41项单元测试。本任务文件的差异空白检查通过；全树原有治理目录尾随空格与两个canvas未修改、未纳入提交。修复提交`16fa557`经GitHub API按原SHA上传（Git HTTPS超时），以force=false快进远端main并核验本地main、origin/main与GitHub main一致。远端[run 42475601399](https://github.com/Lsiming/recsys-knowledge/actions/runs/42475601399)的Python 3.9和3.13两个job及所有检查步骤均success。
