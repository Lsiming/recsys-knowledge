# Agent 执行规则

本文件是本仓库所有会话与 Agent 的统一入口。`CLAUDE.md` 仅转向本文件；不另建一份 `agent.md` 维护重复规则。用户当前明确指令优先，已有授权持续有效，不因模板或旧交接重复请求许可。

## 1. 启动与阅读路由

1. 检查 `git status --short --branch`、`git log -5 --oneline` 和相关 diff；识别已有或并发改动，不清理他人文件。
2. 依次阅读 [README](README.md)、[当前记忆](PROJECT_MEMORY.md)、[总交接](SESSION.md)、[任务队列](TODO.md)。首次进入或范围变化时读 [项目背景](docs/PROJECT_BACKGROUND.md)。
3. 修改前读 [上下文与多会话协作](docs/规范/上下文与多会话协作.md)，调研和实验另读 [研究工作流](docs/规范/研究工作流.md)。按任务读取专题与独立交接，不默认扫描所有论文、历史和日志。
4. 多步任务用简短计划说明交付与验证；已有方案可直接补齐，不机械建文档。纯问答无新事实时不更新整套上下文。

## 2. 本项目边界与研究要求

- 本项目用于推荐和交易场景前沿模型的调研学习。具体任务、业务定义、论文与评估口径按用户当前任务确认，不能从参考项目继承。
- 区分“论文/作者报告”“本仓库复现”“分析推断”“待验证假设”；关键结论记录来源、版本、检索日期和适用条件。未读全文、未执行代码或未核实来源必须如实标注。
- “前沿/最新”需要注明检索截至日期；优先原论文、官方代码和官方技术报告。二手解读可辅助，不据此编造原文指标或业务收益。
- 方法比较写清任务、人群、数据、基准、指标和资源差异；推荐、交易、因果及业务收益结论不能相互替代。
- 复现实验记录真实源码、配置、输入、运行环境、seed、输出及失败。调参集和最终测试集分开；已用于多轮选择的测试集不称独立验收集。
- 本地文档维护、只读资料查询和既定范围内可逆修改直接推进。待办和候选方向本身不触发新任务；高成本计算或新外部写入按具体任务已有授权判断。

## 3. 上下文与并发

- 根文件按职责维护：README 导航；背景长期边界；MEMORY 当前事实和决定；SESSION 总交接；TODO 有效任务。详细笔记、实验和失败证据放专题，不把流水账复制进根文件。
- TODO 是唯一任务注册表；每个任务有稳定 ID、负责人、写入范围、状态与完成条件。并行会话使用各自的 `docs/会话/<任务ID>.md`，不能轮流覆盖根 SESSION。
- 活跃任务并行修改时优先独立本地分支/worktree。共享工作目录只用于不重叠文件的编辑；分支切换、暂存和提交必须串行由明确的整合会话负责。
- AGENTS、README、MEMORY、SESSION、TODO 和共享索引由当轮明确的整合会话维护；专题会话在任务交接记录待合并内容。单会话时由该会话兼任整合者。
- 写入和提交前重新读取目标文件与 Git diff，合并已有增量。复杂整体替换先保存原文；历史归档只供查证，不能恢复旧任务状态或旧授权。
- 任务从进行中转入交接、阻塞或完成时更新独立交接；影响主线的变化由整合者同步总交接、队列及稳定记忆。
- 默认由当前 Agent 自查。用户或适用规则明确要求子 Agent 时才委派，并明确文件归属；未执行独立审查不得声称已通过。

## 4. 本地 Git 维护

- 用户已明确只做本地 Git。不要配置 remote、upstream，不执行 fetch、pull、push 或创建远端 PR；外部论文与官方代码的只读访问按调研需要进行。
- 每项完成且通过适用验证的文件修改默认做一次中文本地提交；用户明确不提交时遵从。问答无文件修改不提交。独立工作树可提交自己的分支，由整合者在本地主线合并。
- 仅 `git add <本任务明确文件>`，核查 `git diff --cached`；不使用 `git add .`、`git add -A` 或 `git commit -a` 混入其他会话内容。索引已有他人改动时保留，不擅自提交或取消暂存，先使用隔离工作树或协调串行提交。
- 不回退、删除或整理无关改动；不使用 `git reset --hard`、`git checkout --`、`git clean -fd`。分支/worktree 清理先确认已整合和无未保存内容，不自动强制删除。
- 日志、真实样本、模型权重、凭证、缓存及本地环境不入 Git；`.gitignore` 是辅助，提交前仍检查内容。笔记、实验方案、代码和小型汇总附件按任务提交。

## 5. 验证与收尾

- 文档变更：核对事实和当前决定，执行 `python3 scripts/check_context.py` 与 `git diff --check`；暂存后执行 `git diff --cached --check`。检查器只验证文档入口、相对链接目标、模板占位符泄漏及无远端约定，不验证科研结论或并发锁。
- 代码变更：另做相关语法检查与必要的语义/smoke 验证。真实实验必须核验真实产物；未运行的训练、指标或业务验证明确写出。
- 有新稳定结论才更新 MEMORY；根 SESSION 保持简短，以任务交接和证据链接承接细节。已完成任务移出有效队列，保留任务交接和 Git 历史。
- 最终说明交付、实际验证、未覆盖范围及本地提交；不把文档约定写成已实现的自动门禁。

默认中文沟通与文档；代码、模型名、命令和引用保留原文。新资料按 [文档导航](docs/README.md) 落位。
