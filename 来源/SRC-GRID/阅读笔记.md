# 用 GRID 看清语义 ID 推荐的三个环节

GRID 的 README 将实践分成物品文本向量、语义 ID 学习、推荐生成三个环节。这使表示、离散化和推荐模型之间的接口能够被分别讨论，适合为后续代码精读建立路线。

## 从物品文本到推荐输出

[Overview](https://github.com/snap-research/GRID/blob/2fe3475b2d369580234093f35d52b1a2f54d0472/README.md#L10)说明，先从物品文本得到向量，再用残差量化技术学习层次化 ID，最后由 Transformer 生成推荐的 ID Token。Quick Start 分别给出这三个环节的运行入口，连接 [表征与物品编码](../../知识库/模块/表征与物品编码.md)、[召回与检索](../../知识库/模块/召回与检索.md)和 [解码](../../知识库/模块/生成机制与约束解码.md)。

[训练推荐模型的说明](https://github.com/snap-research/GRID/blob/2fe3475b2d369580234093f35d52b1a2f54d0472/README.md#L85)提到额外增加一个层级以区分重复语义 ID。这个例子解释了为什么“表示相似物品”与“唯一标识可返回的物品”是两个问题；具体去重实现仍需阅读源码。

## 框架实现与原论文实现需要区分

[Supported Models](https://github.com/snap-research/GRID/blob/2fe3475b2d369580234093f35d52b1a2f54d0472/README.md#L108)列出若干语义 ID 构建方法和 TIGER 实现，Citation 指向实践手册。GRID 是 Snap 团队的框架入口，不能因其中实现 TIGER 就称为 TIGER 原作者官方代码，也不能把多个实现视为独立效果复现。
