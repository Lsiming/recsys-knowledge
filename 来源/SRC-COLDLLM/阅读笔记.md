# ColdLLM：用大语言模型模拟冷物品交互

ColdLLM解决的是**严格的物品冷启动**：新物品没有任何历史交互，因而不能像热物品那样从用户—物品图中学到行为Embedding。论文的关键转变不是把物品内容直接映射成一个“看起来像行为”的向量，而是先让模型生成一小批可能与该物品互动的用户，再把这些伪交互送回已有推荐器的Embedding更新流程。这样冷物品可以使用和热物品相同的协同优化接口，同时把LLM的文本世界知识用于判断内容与用户兴趣的关系。

采用arXiv:2402.09176v2（WSDM 2025，DOI 10.1145/3701551.3703546）。以下数字和流程均来自作者报告；本文已核对源码正文、公式、表格和在线实验，没有运行官方实现，也没有把论文的线上结果当作本仓库复现。

## 从“内容映射”转向“行为模拟”

设用户集合为\(\mathcal U\)，物品分为有历史交互的\(\mathcal I_w\)和严格冷启动集合\(\mathcal I_c\)。热物品\(i\)有用户序列\(s_i\)，而冷物品\(j\)满足\(s_j=\varnothing\)。传统方法以内容\(c_i\)生成一个合成向量，再让它靠近热物品行为向量；这会留下内容—行为差距，而且把内容表示和协同表示混在同一推荐阶段。DropoutNet、MTPR、CLCRec等通过随机丢弃行为向量提高鲁棒性，DeepMusic、MetaEmb、GAR、ALDI等通过蒸馏、生成或对齐逼近行为分布，但这些方法仍没有产生真实意义上的用户—物品训练边。

ColdLLM把目标改成生成用户序列：

\[
\hat s_i=\operatorname{ColdLLM}(c_i,\mathcal U,\mathcal H,\mathcal C),\quad i\in\mathcal I_c,
\]

其中\(\mathcal H\)是历史交互，\(\mathcal C\)是全体物品内容。随后使用已有推荐器的行为Embedding优化器：

\[
e_i^{(c)}=\operatorname{Emb}_{opt}(c_i,\hat s_i,\mathcal E),
\]

\(\mathcal E\)包含已训练的用户与热物品向量。离线训练可以把伪交互作为额外样本；工业在线链路只更新冷物品向量，避免伪边反过来改变全体用户和热物品。

这一步是论文最重要的边界：生成的是“可能的交互边”，不是最终推荐列表，也不是对真实点击概率的校准估计。伪边必须带有生成时可见的信息和筛选规则，不能在上线后把它解释成已经发生的曝光或点击。

## 过滤—细化漏斗把LLM成本压到可用范围

直接对数十亿用户逐个询问LLM不可行。ColdLLM先用一个与LLM耦合训练的过滤器，把用户从十亿级缩到几十或几百，再用LLM做精细判断。

### 第一阶段：内容—行为过滤

对冷物品内容输入LLM，取最后一层Token表示的平均池化，再经映射函数得到过滤向量：

\[
f_i=F_I\left(\frac{1}{|c_i|}\sum_{j=1}^{|c_i|}E^{(L)}(c_i)[j]\right).
\]

用户侧用其行为Embedding和内容列表\(C_u\)经\(F_U\)映射。通过内积选取Top-\(K\)：

\[
s_i^{(f)}=\operatorname{TopK}\{F_U(e_u\mid C_u)^\top f_i:u\in\mathcal U\}.
\]

论文建议使用FAISS等相似度索引加速。文中把索引检索写成近似\(O(1)\)，这只表示相对于逐用户扫描的工程抽象；真实延迟仍取决于索引规模、向量维度、更新和并发，不能当成与用户数无关的理论复杂度。

过滤器训练时由LLM生成的行为判断作为监督的一部分。它弥补了纯协同模型看不到内容语义的缺陷，但仍只是候选筛选，不承担最终伪点击判定。

### 第二阶段：相关历史与二元细化

对每个候选用户，先用过滤向量从其历史内容中取Top-\(L\)相关物品：

\[
C_u^{(f)}=\operatorname{TopL}\{f_i^\top f_j:j\in C_u\}.
\]

再构造固定提示、用户历史文本和冷物品文本三部分提示，要求LLaMA只回答“yes/no”：

> Given the user interacted with [Text(\(C_u^{(f)}\))], determine whether the user will interact with [Text(\(c_i\))] by answering Yes or No.

输出\(\hat Z_{u,i}\in\{0,1\}\)。论文当前实现是二元决策，作者指出后续可扩展成连续分数。正文的细化集合定义是遍历过滤用户并保留回答“Yes”的用户；部署段另报告识别20名合格用户，但未完整披露候选不足或达到数量时的停止策略。不能据此补写一个通用的“凑满20人”算法。生成数据的数量、上下文长度和提示模板都会影响Embedding更新。

### 训练和部署的耦合

LLM先用热物品的真实用户—物品对做监督微调，使其学习从用户历史和物品内容预测交互；过滤器再与LLM的判断共同训练，使低成本的向量检索尽量保留会被细化阶段接受的用户。在线时，冷物品到达后依次执行：LLM内容编码、向量过滤、LLM细化、只更新该物品Embedding，并把新向量送入现有召回/排序服务。这个接口允许保留原推荐器和索引系统，但增加了冷物品发布时的异步计算任务。

训练信号并非只有真实点击与真实负反馈。在线数据把点击记为正行为、忽略记为负行为、未推荐记为未观测；作者分别进行正/负1:1采样，以及额外的正/未观测1:1采样。离线只使用正/未观测1:1采样。**未观测不等于用户不喜欢**，这使模拟器仍依赖采样监督的假设，而不是恢复了真实点击概率。LLM在注意力Q/K/V投影和FFN上加入LoRA低秩更新，以适配推荐场景。[§4.3，PDF第5页](https://arxiv.org/pdf/2402.09176v2#page=5)。

过滤器同时使用两类监督：行为分支以\(s^{(B)}_{ui}\)表示用户行为向量与物品内容映射的内积，最小化\(-\sum_{(u,i,j)}\log\sigma(s^{(B)}_{ui}-s^{(B)}_{uj})\)的BPR损失，并借用ALDI的对齐损失；耦合分支另以LLM的Yes/No标签\(\hat Z_{ui}\)做二元交叉熵，促使低成本过滤接近LLM的选择。原文将耦合分支的内积\(\hat Y^{(L)}_{ui}\)直接写入\(\log\hat Y\)和\(\log(1-\hat Y)\)，未写把分数变为\((0,1)\)概率的sigmoid或其他约束。因此可以解释其监督意图，但不能称原公式已完整说明可计算实现；译文保留原式并加注，尚未核对官方代码。

论文给出的部署估算是：过滤约60 ms；使用微调LLaMA-7B细化每个用户—物品对约200–400 ms，总细化少于8 s；Embedding更新约120 ms。三台\(8\times\)A100机器约每小时处理8640个冷物品。这里的数值是作者的特定硬件、并行度和实现配置，不能转化成通用的LLM在线延迟结论；尤其不能把FAISS的抽象复杂度当成端到端耗时。

## 证据：冷物品提升明显，但真实收益仍受协议约束

离线实验使用CiteULike（5551用户、16980物品、204986交互）和MovieLens（6040用户、3883物品、1000210交互）。每个数据集指定20%物品为冷启动，冷物品交互再按1:1划分验证和测试；其余热物品按8:1:1划分训练、验证、测试。正文未明确冷物品的抽取是否随机，不能补作已知协议。MovieLens脚注链接指向10M版本，而统计量接近1M规模，精确采用版本仍需作者或实现确认。作者在MF、NGCF、LightGCN三种骨干上与DropoutNet、MTPR、CLCRec、DeepMusic、MetaEmb、GNP、GAR、ALDI、UCC和MI-GCN比较，使用全排序Recall@20与NDCG@20，并随机抽取2000名用户。[§5.1，PDF第6页](https://arxiv.org/pdf/2402.09176v2#page=6)。

LightGCN骨干上，CiteULike整体Recall/NDCG为0.2285/0.1747，冷物品为0.3601/0.2126，热物品为0.3252/0.2156；MovieLens对应整体0.1506/0.2468、冷物品0.1759/0.1762、热物品0.3314/0.3186。论文引言贡献概括为冷推荐性能提升21.69%；表格中的提升百分比按不同骨干和数据集变化，不能把21.69%当作所有场景的统一增益，也不能理解为每个表格单元都最优。

消融显示过滤与细化都重要：去掉LLM语义过滤、行为过滤或细化阶段都会下降；在CiteULike过滤策略的采纳率中，随机过滤为8.18%，去掉LSF或BF分别为80.45%和81.33%，完整ColdLLM为85.96%。\(K\)过小会漏掉潜在用户，过大又会把噪声带入细化；作者观察到整体/热物品和冷物品的最优\(K\)不相同，说明“多保留用户”不是单调收益。

在线A/B实验持续两周，每组5%用户，冷启动窗口定义为物品发布后两小时。相对Random，Cold-PV、Cold-PCTR和Cold-GMV分别提升11.45%、5.60%、23.80%；相对MetaEmb为9.20%、4.35%、18.25%；相对ALDI为7.25%、3.70%、16.90%。这是作者在一个电商平台上的报告，缺少流量分层、置信区间、长期回流和伪交互错误率等细节；因此它支持“该实现可产生线上收益”，不能单独证明LLM模拟在其他业务或其他冷启动定义下普遍有效。

## 与其他生成数据路线的关系

ColdLLM和Agent4Rec都生成行为，但前者针对没有历史的**冷物品**，生成的是用于更新物品Embedding的一次性用户集合；后者模拟有状态用户在推荐环境中的多轮动作。前者重点是冷启动数据注入和工业吞吐，后者重点是行为分布与策略评估保真，二者不能共享“用户模拟已被验证”的结论。

它也不同于DiffRec等直接对交互向量去噪的方法：DiffRec学习观测交互向量的连续恢复，ColdLLM先生成离散用户—物品关系，再调用现有协同优化器；一个改变生成对象，一个改变训练数据。与TIGER等语义码生成相比，ColdLLM不生成物品码，不负责合法码约束，而是为现有目录中的冷物品补协同信号。

## 可复用的验收条件和限制

将ColdLLM引入知识库时，至少应保留四个条件：冷物品定义为无历史交互；过滤和细化的输入只能使用上线时已知内容与历史；伪交互只更新允许的参数；最终价值在独立真实曝光/点击/交易上验证。若把生成的用户集合混入用户Embedding或热物品训练，错误会沿图传播，实验也可能因额外训练量而产生虚假增益。

还需补查的问题包括：Yes/No输出是否校准、不同人群和长尾物品的错误率、冷物品随时间获得真实交互后何时切换到真实行为、过滤器是否随目录漂移更新，以及在线实验是否对冷物品曝光量和库存资格做了控制。论文没有给出这些问题的完整协议，不能从现有表格推断其答案。
