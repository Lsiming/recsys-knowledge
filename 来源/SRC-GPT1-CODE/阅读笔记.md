# GPT初代官方实现：把论文中的角色落实到张量和参数

[返回GPT论文笔记](../SRC-GPT1/阅读笔记.md) · [学习思考](../SRC-GPT1/学习思考.md)

论文给出通用模型，公开脚本展示ROCStories两候选任务的微调。这里固定`a69b5c43b0452462890bca8ff92fb75dee9290cf`，静态核对`train.py`、词表和参数形状；未下载权重或运行原训练。下文的函数与行号均对应这一版本：[train.py](https://github.com/openai/finetune-transformer-lm/blob/a69b5c43b0452462890bca8ff92fb75dee9290cf/train.py)。

## Post-LN与GELU的实际顺序

`block`在第140–148行先计算注意力，执行`norm(x+a)`，再计算FFN并执行`norm(n+m)`，因此是Post-LN。`mlp`的中间宽度是输入的4倍；`gelu`在第22–23行采用

$$GELU(x)\approx\tfrac12x\left[1+\tanh\left(\sqrt{2/\pi}(x+0.044715x^3)\right)\right].$$

这是逐元素激活；`conv1d`的`rf=1`分支实际按最后特征维作仿射投影，不在相邻Token间卷积。注意力负责跨位置交换，FFN独立变换各位置。`mask_attn_weights`用含对角线的下三角，把禁止分数替换为$-10^9$，不是把分数简单乘0。

## 共享表为何还包含位置行

`model`第164行的`we`形状为`[n_vocab+n_special+n_ctx, n_embd]`。输入`X[...,0]`存Token ID，`X[...,1]`存偏移到位置区的ID，`embed`查两行后相加。论文式(2)分写Token与位置表，脚本为实现方便合并存放。

第175行`tf.matmul(lm_h, we, transpose_b=True)`使用整个`we`投影，logits包含基础词表、新标记和位置行；基础词表加特殊Token才是文本标签的有效ID范围，位置行在这里额外参与分母。不能把此脚本原样解说为“只投影到40,478词表项”，也不能因此改写论文式(2)只绑定Token表的表达。

这仍是同一个变量的输入/输出参数绑定；它的梯度把各使用路径相加。通用数学见[词表预测与梯度](../../知识库/概念/语言模型的词表预测与交叉熵.md#梯度怎样穿过lm头和共享embedding)。

## 错位标签与损失平均

第174–178行用`h[:, :-1]`预测`X[:, 1:, 0]`；`M[:,1:]`乘逐位置交叉熵，再除以本序列有效目标数量。因此输入有效mask与监督目标在索引上错开；不是只对最后位置算LM损失。`mgpu_train`第203–208行再计算分类平均损失加`lm_coef`乘LM平均损失。

`transform_roc`第229–245行在全零数组前部写入每条有效序列，并令相应mask为1，即右填充；所有数组位置仍分配位置ID。此实现的`M`只用于LM Loss，Attention仅用因果mask。有效Token都在填充之前，故其因果前缀不会读取尾部填充；若改成左填充或中间有空洞，必须重新处理Key mask与位置编号，不能直接复用这个结论。一般做法见[遮罩与填充](../../知识库/概念/Attention遮罩与填充.md#左填充和右填充怎样选择)。

## 分类Token怎样定位

第370–375行追加`_start_`、`_delimiter_`、`_classify_`。`transform_roc`把开始符、故事、分隔符、候选结尾、分类符排成每个候选的输入。第181–182行先比较Token ID是否为`clf_token`，再gather对应状态，因此图1中的Extract是分类读出角色，实际字面Token为`_classify_`。

`argmax`返回首个命中位置；若没有命中会退回0，所以正确性依赖构造器保证每条序列有一个分类Token。不是任何任意文本数组都能靠argmax自动找到“语义句尾”。取出的两条候选状态经共享标量头，重组成`[batch,2]`跨候选分类；不能把这份任务脚本当作论文所有任务头的共同实现。

## 发布参数形状怎样计数

[encoder_bpe_40000.json](https://github.com/openai/finetune-transformer-lm/blob/a69b5c43b0452462890bca8ff92fb75dee9290cf/model/encoder_bpe_40000.json)含40,478个条目，[params_shapes.json](https://github.com/openai/finetune-transformer-lm/blob/a69b5c43b0452462890bca8ff92fb75dee9290cf/model/params_shapes.json)含146组形状。只需对各形状的维度乘积求和，无需下载权重：

$$N=40478\times768+512\times768+12(12\times768^2+13\times768)=116,534,784.$$

每Block包含4组注意力投影、2组FFN投影、相应偏置和2个带缩放/偏移的LN；共享输出不再另加一份词表矩阵。微调新增标记、分类头和上下文裁剪会改变实际参数量，需另计。这里是已发布形状清单的计数，不是实测显存或计算量。

## 迁移层数不等于骨干深度

第405–418行加载参数，将两张表合并后按`n_transfer`决定赋值前多少组参数。`1+n_transfer*12`里的12对应每个Block参数数组的个数；而`model`仍循环`n_layer`次。少迁移几层不代表只执行几层。该静态路径帮助解释论文图2，但不补足论文未披露的全部消融协议。
