# Push触达与时机：2022—2026年工业论文路线

Push的关键约束是用户没有主动打开推荐流：系统要决定是否打扰、何时打扰，以及发送多少。内容点击率高不代表此刻发送有增量收益，用户本来就可能回访；连续通知还会影响后续响应、权限关闭和计算成本。因此，时机论文应先按决策对象区分，再比较模型与实验。

截至2026-11-09，本轮筛出13篇互联网公司参与的相关论文，正式题名、公司、年份、出版入口和阅读范围集中在[候选表P75—P87](候选论文.md#push触达与时机)。最贴近发送时机的是快手TIM和字节STEPS；LinkedIn的CIKM2022、KDD2022与2025年Decision Transformer工作则提供“发送或等待”的长期决策路线。推荐顺序按问题贴合度与证据可读性选择，不表示跨平台效果排名。

### TIM：先学一天中哪些时段更适合触达

TIM把长期通知接收、点击、观看等交互组织成“天×时槽”，用Temporal Attention Unit、旋转位置编码与日期/时间信息建模周期和跨日变化。输出是全天各槽响应概率，而不是只预测当前时刻。给定日配额后，再把额度分配到各槽并控制累计发送节奏。这适合“配额规则相对稳定，但统一时刻发送太粗”的业务起点。依据为[固定v1全文](https://arxiv.org/html/2406.07067v1)§2—3；它主要预测响应，不直接估计发送相对不发送的因果增量。

作者在§3.4 Table 3报告：相同配额分配算法下，以均匀发送为对照，CTR相对提升1.217%、DAU提升0.100%。观看时长提升0.066%的p值为0.11；权限关闭变化也未显著，不能据此证明打扰下降或两策略等效。正式出版是[ICMR2024](https://doi.org/10.1145/3652583.3657614)，不能误记为KDD/SIGIR。

### LinkedIn：把等待当作可以学习的动作

CIKM2022工作针对非强时效的批量通知：在预定检查点读取用户近期访问、历史通知数、badge等状态，从队列候选中决定发送或跳过。Double DQN学习后续回访价值，并用离线策略评价筛选。与TIM的全天配额分配相比，它让当前少发与后续状态联系起来；仍依赖检查时刻与日志动作覆盖。[固定v1全文](https://arxiv.org/html/2202.03867v1)§V-B Table I的一周线上A/B，相对生存分析监督基线，报告Sessions +0.30%、通知卡片量−3.49%、CTR +4.53%、取消关注通知动作−4.37%，作者报告均p<0.05。这是短周期策略实验，不等同长期留存已经充分验证。

KDD2022[多目标工作](https://arxiv.org/html/2207.03029v1)针对近实时通知，把session、点击、发送量等奖励放入离线强化学习，并使用Conservative Q-Learning缓解分布外动作的价值高估；不同决策间隔也进入折扣。这与前一篇的批量通知间隔优化是不同任务和实验。其一步重要性采样评价存在作者承认的系统偏差，不能将离线策略曲线直接当作无偏长期收益。

2025年[多目标Decision Transformer预印本](https://arxiv.org/html/2509.02458v1)把轨迹中的状态、动作和目标回报作为序列训练，用状态相关的回报提示驱动动作选择。“Generative”生成的是决策动作，不是通知文案。§6.3 Table 1在2%用户、每次一周的A/B中，报告所选最佳DT策略相对CQL的Sessions +0.72%、发送量−1.68%，CTR无统计显著变化；特征与工程链路也有变化，不能将全部收益归于DT结构。固定v1写明Under review，本轮未核实其正式会议身份。

### STEPS：连下次何时决策也一起学习

STEPS把固定轮询改为自触发闭环：基于Decision Transformer的规划代理通过门控序数回归预测下一次调用时间，执行代理按轨迹奖励判断是否发送。轻量过滤器在昂贵召回/排序前筛掉低价值请求，并限制不合理规划；直播等业务事件仍可触发系统，因此并非完全取消外部事件。方法见[固定v1全文](https://arxiv.org/html/2608.01949v1)§3，出版身份见[RecSys2026 DOI](https://doi.org/10.1145/3773078.3831932)。

作者在§4.1 Table 1的抖音14天、设备随机A/B中，相对预先规划频次的生产基线，报告User Active Days +0.2843%、关闭Push权限的用户数−1.9089%、资源消耗−79.42%。资源下降主要来自轻量过滤器，不能解释成单纯“更准地预测时机就省了79%”。这一方向最直接覆盖“何时再决策+届时是否发”，但需要轨迹数据、执行与规划协调、过滤和事件兜底，工程投入高于单独替换时槽预测器。

## 补足生存模型、分配与打扰视角

[P80 · DeepPvisit](候选论文.md#p80)从深度生存模型切入访问时间与通知决策，适合补足time-to-visit视角；它在WWW2023 Companion，不能算WWW主会。[P81 · Twitter未来行为模型](候选论文.md#p81)用model-based RL考虑跨天影响，适合作为长期价值建模补充，但本轮未核实正式会议。

[P82 · Meta Fair Notification](候选论文.md#p82)把通知类型与用户机会建模为拍卖/公平分配，适合多业务争夺触达容量的场景。它处理资源分配与pacing，不是单用户最佳发送时间模型。[P86 · Google/CMU TOCHI2022](候选论文.md#p86)提供用户打扰偏好证据：一周、35人体验采样发现，减少不想要提醒时，抑制可能比延迟更符合偏好；内容也会显著影响偏好。小样本用户研究不能替代生产增长A/B。

[P87 · 字节SIGIR2026 Industry工作](候选论文.md#p87)被STEPS作为预规划基线所依托的引用，可用来追查“活跃建模—uplift—频次/排时”路线。本轮只核实题名、机构、会议与引文位置，独立模型机制和收益待取得正文后判断。

一个容易混淆的背景来源是[《A State Transition Model for Mobile Notifications via Survival Analysis》](https://doi.org/10.1145/3289600.3290981)：尽管[arXiv版本](https://arxiv.org/abs/2207.03099v1)在2022年上传，正式发表是WSDM2019，不计入2022—2026年的新论文。

## 内容推荐与发送时机分别看

[P83 · HGenPush](候选论文.md#p83)，快手KDD2026，用异构生成式推荐处理视频与作者等候选；[P84 · PushGen](候选论文.md#p84)，快手WSDM2026，用LLM生成通知文案；[P85 · LinkedIn跨域GNN](候选论文.md#p85)，CIKM2025，利用跨域行为改进通知表示。这些都值得作为Push内容链路阅读，但时间特征、时序聚合或CTR提升本身，不等于学到了何时触达。

如果要从业务问题选择第一篇：已有每日配额、先改善日内分发，读TIM；主要痛点是疲劳和频控，读LinkedIn的两篇2022论文；希望进一步统一长期轨迹、唤醒时间与调用成本，再读2025 DT和STEPS。多业务配额冲突补Fair Notification，用户打扰偏好补TOCHI。评估时同时报告活跃/回访、发送量、权限关闭或投诉与总成本，CTR仅是其中一项；不同平台、基线、随机化单位与实验周期的相对提升不能直接排序。相关基础见[长期策略模块](../模块/探索、长期收益与策略学习.md)、[多目标模块](../模块/多任务学习与多目标决策.md)、[序列建模](../模块/用户兴趣与序列建模.md)、[服务效率](../模块/在线服务、更新与计算效率.md)与[因果评估](../模块/评估、偏差与因果收益.md)。
