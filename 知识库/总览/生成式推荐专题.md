# 生成式推荐：沿共同问题理解新解法

生成式推荐适合作为贯穿推荐系统的研究视角。它可能改变候选的产生方式，也可能改变列表决策、物品编码、监督形式与计算路径。因此，先确定解决哪个共同问题，再判断“生成”在哪个环节发生。

## 为什么引入生成，收益需要哪些条件

推荐面临的共同困难包括行为稀疏、内容与协同信号割裂、多阶段候选损失，以及对话/内容创作难以用单一评分接口表达。生成模型可补充语义数据、生成已有物品的标识，或合成新内容；这些改变可以分别发生，不能一概理解为替换全部推荐链路。[DMT综述§1–2](../../来源/SRC-GENREC-DMT/阅读笔记.md#从匹配到生成究竟改变哪一步)给出研究动机，[LongTalk对照](../../来源/SRC-GENREC-LONGTALK/阅读笔记.md)进一步提醒从问题和强基线出发。

世界知识来自具体预训练与输入信息，规模收益依赖架构、数据和计算，对话/创作则有不同任务需求。按行为训练的生成器不天然拥有语言常识，使用文本的传统推荐器也不天然缺乏语义。离线命中、模拟奖励和线上业务收益分别验证，不能由“生成式范式跃迁”直接推出普遍优越性。

## 数据—模型—任务是一组交叉视角

[DMT综述](../../来源/SRC-GENREC-DMT/阅读笔记.md)采用广义定义：流程任一阶段使用生成模型即纳入生成式推荐。三层描述的是介入位置，同一系统可同时占多个位置；LLM、LRM和扩散也不是互斥的完整系统类型。

| 视角 | 关键设计 | 在现有模块中的位置 |
|---|---|---|
| 数据增强 | 生成内容、表示、行为、图结构，或Agent闭环轨迹 | [数据与标签](../模块/数据、样本与标签.md#生成数据进入推荐训练之前)、[合成反馈问题](../问题/生成数据怎样补充真实推荐反馈.md) |
| 数据统一 | 跨域、多任务、多模态、一个模型服务多场景 | [多场景与冷启动](../模块/多场景、迁移与冷启动.md#统一接口以后仍有域间差异)、[训练与对齐](../模块/训练目标与偏好对齐.md) |
| 模型 | 预训练LLM适配、推荐原生大型模型、扩散 | [生成机制](../模块/生成机制与约束解码.md#三条模型路线需要落到同一输入输出接口)、[表征编码](../模块/表征与物品编码.md) |
| 任务 | Top-K、内容创作、对话、解释、推荐推理 | [输出对象与评估](../问题/生成式推荐怎样选择输出对象与评估目标.md) |
| 验证与服务 | 任务指标、合法目录、真实反馈、整链路成本 | [评估](../模块/评估、偏差与因果收益.md#生成式系统要同时验收结果与中间接口)、[服务效率](../模块/在线服务、更新与计算效率.md) |

例如“LLM写商品描述→SASRec排序”属于数据增强；“量化物品→生成语义码→查目录”改变候选产生；“生成个性化标题”改变可展示内容。先沿这三个例子确定职责，再用下面五维对齐具体方案。

## 五个维度分别看

| 维度 | 需要问什么 | 容易混淆的地方 |
|---|---|---|
| 生成对象 | 输出物品标识、列表排列、偏好向量，还是推荐内容？ | 生成解释文本与从物品库选出可执行推荐是不同任务 |
| 表征 | 输入输出使用独立 ID、文本、连续向量还是语义码？ | 语义 ID 是编码选择，不等于特定骨干或训练目标 |
| 架构 | 是序列转导、编码器/解码器、扩散还是混合结构？ | Transformer/HSTU 名称不能独自决定输出方式 |
| 训练 | 用似然、对比、排序、偏好还是奖励信号？ | 训练时拟合下一项，不自动等于推理时以 Token 逐步检索物品 |
| 系统范围 | 替换召回、重排、某种表征，还是联合多个阶段？ | 论文称“端到端”时仍需核对实际候选、过滤与回退 |

[生成式清单](../../来源/SRC-GENREC-LIST/阅读笔记.md)横跨 LLM、Semantic ID、架构和 Diffusion；[Item ID 清单](../../来源/SRC-ITEMID-SURVEY/阅读笔记.md)把标识构建、对齐、生成与加速分别组织。这里采用上述维度，是为了避免把不同层次的技术当作互斥类别。

## 如何与已有方法比较

先固定任务：生成检索应与同候选预算的召回比较；候选内列表生成应与同候选集的重排比较；统一系统则同时说明输入信息、阶段总预算和最终指标。不能把全库生成命中率与负采样排序数字直接横比。

再拆收益来源：物品表示变了多少、骨干变了多少、训练信号变了多少、搜索预算变了多少。最后计入合法映射、过滤补位和更新成本，具体见 [评估](../模块/评估、偏差与因果收益.md)与 [服务效率](../模块/在线服务、更新与计算效率.md)。传统推荐中的 VAE 等生成路线也保留在共同问题中，避免把研究历史压成“LLM 之前/之后”两块。

完整主干见 [推荐系统总图](推荐系统总图.md)。本页复用各模块正文，首批论文的身份和待阅读边界见 [候选表](../阅读/候选论文.md)。

[P5精读](../../来源/SRC-P5/阅读笔记.md)及[语言统一个性化任务问题](../问题/如何用语言接口统一个性化推荐任务.md)已提供论文依据：任务接口、物品Token来源和候选协议是三个分别需要设计的维度；未见措辞泛化与新物品全库召回不可混称零样本能力。

[LC-Rec精读](../../来源/SRC-LCREC/阅读笔记.md)与[语义码比较](../问题/用语义短码直接检索物品.md)补充语言协同桥梁：索引构建、内容/行为调优、合法输出分别需要证据；软平衡分配、全库评估和注意力复杂度都不能单独证明大规模唯一寻址或服务优势。

[HSTU论文精读](../../来源/SRC-HSTU-PAPER/阅读笔记.md)补充行为模态和工业扩展路线：[物品行为交错](../问题/序列怎样统一候选条件预测.md)统一候选响应监督，[M-FALCON](../问题/目标感知排序怎样复用历史计算.md)摊销候选打分。GR不必生成语义码或自然语言，1.5万亿总参数不等于稠密编码器规模；列表联合生成仍属本篇未来工作。

[OneRec精读](../../来源/SRC-ONEREC/阅读笔记.md)连接[会话联合生成](../问题/列表顺序与前缀依赖怎样建模.md#从候选指针到全库会话码生成)与[迭代偏好对齐](../问题/生成式推荐怎样从似然训练走向偏好对齐.md)：从下一物品码扩展为整列表码，再用RM标注的胜负对更新分布。它不同于HSTU候选条件响应预测，离线RM评分、线上观看和服务资源分别判断。

[S-DPO精读](../../来源/SRC-SDPO/阅读笔记.md)进一步补充[偏好对齐比较](../问题/生成式推荐怎样从似然训练走向偏好对齐.md)：一正多负标题的部分排序与RM生成列表对是两种监督单位；S-DPO实验是给定抽样候选的单项选择，不等同全库码检索或会话生成。

[长度与同质化解码校正](../问题/物品生成怎样校正长度偏差与同质化.md)补充搜索阶段证据：D³取消长度归一化，用协同物品概率引导每步前缀；它改变保留路径，不等于集合多样性硬约束或生成加速。

[Gen-RecSys综述精读](../../来源/SRC-GENRECSYS-REVIEW/阅读笔记.md)把交互生成、LLM与多模态放到共同地图上；进一步按[输出对象与评估目标](../问题/生成式推荐怎样选择输出对象与评估目标.md)比较训练样本、物品结果、解释和内容合成。RAG是检索器给LLM提供输入，LLM特征提取则反向提供推荐输入；分类与评估建议不代表统一模型排名。

## 继续阅读怎样补齐已有主干

现有P5→TIGER→LC-Rec建立语言接口与语义码主干，HSTU与OneRec分别解释行为扩展和会话生成，DiffRec提供交互向量去噪；不必把这些已读工作重新列为待读。新增路线按缺口安排，具体题名、身份核对范围和问题集中在[候选表P59–P71](../阅读/候选论文.md#综述与longtalk补充路线)。

| 优先方向 | 推荐顺序 | 读完应补足什么 |
|---|---|---|
| 数据增强与模拟 | ColdLLM→Agent4Rec | 伪交互怎样加入训练，模拟用户能否预测真实策略变化 |
| 表示与检索接口 | LETTER / LLaRA→TokenRec | 编码如何同时学习语义与协同，离散输入是否仍接连续检索 |
| 扩散输出 | 已读DiffRec→DreamRec→MDGR | 全目录分数、连续目标表示和离散并行码的映射与成本差别 |
| 跨域统一 | FedCGR / UniGCRec | 哪些信息/参数共享，怎样衡量负迁移与隐私边界 |
| 潜推理与工业链路 | LatentR³→已有P42 OneSug→OneMall | 额外推理计算、Query与物品输出、代理奖励及真实替代阶段 |
| 内容与任务评估 | PENS，结合已有评估基础 | 内容真实性、个性化与用户任务完成怎样共同测量 |

上述顺序按知识缺口编排。截至2026-10-30，ColdLLM、Agent4Rec、LETTER、LLaRA、TokenRec、DreamRec、LatentR³、OneMall、MDGR和FedCGR均已完成正文中文PDF、精读及相应问题整合，原文与译文已私有备份并真实登录下载核验。重点队列中尚待完整精读的是UniGCRec、PENS，以及已有候选OneSug、OneRec V2、OneReason和扩展阅读PreferDiff、OneRec-Think，共7篇；这不是综述全部引用的穷尽差集。文章中尚未核实原文入口或发表信息的条目明确保留为线索，不把“零成本”“根除负迁移”“终结级联”等概括用作已证实结论。

数据侧已有[ColdLLM与Agent4Rec比较](../问题/生成数据怎样补充真实推荐反馈.md#模拟反馈的标签与验收需要分开)：冷物品伪交互注入与有状态用户模拟解决不同问题。Agent4Rec有真实离线排序与模拟满意度报告，缺少充分披露的独立协议和真人线上验证；不能由“拟人化”推导可替代在线A/B，也不能把其模拟DAG当成真实因果证据。
