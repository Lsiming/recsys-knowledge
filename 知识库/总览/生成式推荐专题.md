# 生成式推荐：沿共同问题理解新解法

生成式推荐适合作为贯穿推荐系统的研究视角。它可能改变候选的产生方式，也可能改变列表决策、物品编码、监督形式与计算路径。因此，先确定解决哪个共同问题，再判断“生成”在哪个环节发生。

## 五个维度分别看

| 维度 | 需要问什么 | 容易混淆的地方 |
|---|---|---|
| 生成对象 | 输出物品标识、列表排列、偏好向量，还是推荐内容？ | 生成解释文本与从物品库选出可执行推荐是不同任务 |
| 表征 | 输入输出使用独立 ID、文本、连续向量还是语义码？ | 语义 ID 是编码选择，不等于特定骨干或训练目标 |
| 架构 | 是序列转导、编码器/解码器、扩散还是混合结构？ | Transformer/HSTU 名称不能独自决定输出方式 |
| 训练 | 用似然、对比、排序、偏好还是奖励信号？ | 训练时拟合下一项，不自动等于推理时以 Token 逐步检索物品 |
| 系统范围 | 替换召回、重排、某种表征，还是联合多个阶段？ | 论文称“端到端”时仍需核对实际候选、过滤与回退 |

[生成式清单](../../来源/SRC-GENREC-LIST/阅读笔记.md)横跨 LLM、Semantic ID、架构和 Diffusion；[Item ID 清单](../../来源/SRC-ITEMID-SURVEY/阅读笔记.md)把标识构建、对齐、生成与加速分别组织。这里采用上述维度，是为了避免把不同层次的技术当作互斥类别。

## 如何与已有方法比较

先固定任务：生成检索应与同候选预算的召回比较；候选内列表生成应与同候选集的重排比较；统一系统则同时说明输入信息、阶段总预算和最终指标。不能把全库生成命中率与负采样排序数字直接横比。

再拆收益来源：物品表示变了多少、骨干变了多少、训练信号变了多少、搜索预算变了多少。最后计入合法映射、过滤补位和更新成本，具体见 [评估](../模块/评估、偏差与因果收益.md)与 [服务效率](../模块/在线服务、更新与计算效率.md)。传统推荐中的 VAE 等生成路线也保留在共同问题中，避免把研究历史压成“LLM 之前/之后”两块。

[P5精读](../../来源/SRC-P5/阅读笔记.md)及[语言统一个性化任务问题](../问题/如何用语言接口统一个性化推荐任务.md)已提供论文依据：任务接口、物品Token来源和候选协议是三个分别需要设计的维度；未见措辞泛化与新物品全库召回不可混称零样本能力。

[LC-Rec精读](../../来源/SRC-LCREC/阅读笔记.md)与[语义码比较](../问题/用语义短码直接检索物品.md)补充语言协同桥梁：索引构建、内容/行为调优、合法输出分别需要证据；软平衡分配、全库评估和注意力复杂度都不能单独证明大规模唯一寻址或服务优势。

[HSTU论文精读](../../来源/SRC-HSTU-PAPER/阅读笔记.md)补充行为模态和工业扩展路线：[物品行为交错](../问题/序列怎样统一候选条件预测.md)统一候选响应监督，[M-FALCON](../问题/目标感知排序怎样复用历史计算.md)摊销候选打分。GR不必生成语义码或自然语言，1.5万亿总参数不等于稠密编码器规模；列表联合生成仍属本篇未来工作。

[OneRec精读](../../来源/SRC-ONEREC/阅读笔记.md)连接[会话联合生成](../问题/列表顺序与前缀依赖怎样建模.md#从候选指针到全库会话码生成)与[迭代偏好对齐](../问题/生成式推荐怎样从似然训练走向偏好对齐.md)：从下一物品码扩展为整列表码，再用RM标注的胜负对更新分布。它不同于HSTU候选条件响应预测，离线RM评分、线上观看和服务资源分别判断。

[S-DPO精读](../../来源/SRC-SDPO/阅读笔记.md)进一步补充[偏好对齐比较](../问题/生成式推荐怎样从似然训练走向偏好对齐.md)：一正多负标题的部分排序与RM生成列表对是两种监督单位；S-DPO实验是给定抽样候选的单项选择，不等同全库码检索或会话生成。

[长度与同质化解码校正](../问题/物品生成怎样校正长度偏差与同质化.md)补充搜索阶段证据：D³取消长度归一化，用协同物品概率引导每步前缀；它改变保留路径，不等于集合多样性硬约束或生成加速。

[Gen-RecSys综述精读](../../来源/SRC-GENRECSYS-REVIEW/阅读笔记.md)把交互生成、LLM与多模态放到共同地图上；进一步按[输出对象与评估目标](../问题/生成式推荐怎样选择输出对象与评估目标.md)比较训练样本、物品结果、解释和内容合成。RAG是检索器给LLM提供输入，LLM特征提取则反向提供推荐输入；分类与评估建议不代表统一模型排名。
