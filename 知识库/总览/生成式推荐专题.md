# 生成式推荐：沿共同问题理解新解法

生成式推荐有三类不同的改变：用模型补充训练信息、从历史生成已有物品的地址或检索表示，以及为用户合成新的展示内容。它们可以组合，也可以只替换原链路中的一个环节。判断一种方法的价值，先确定信息从哪里来、模型生成什么、输出怎样成为可执行推荐，再比较效果和总成本。

## 研究背景：评分接口遇到哪些限制

传统系统对候选物品计算分数$s(u,i\mid h,c)$，以多阶段筛选支撑大目录。它的困难包括早期候选遗漏难恢复、召排目标不一致、稀疏行为难学可靠ID表示，以及内容创作和多轮交流难压进单一分数。生成模型提供新的信息和决策接口，例如把物品$i$编码成$L$个码字，直接学习

$$p_\theta(z(i)\mid h,c)=\prod_{\ell=1}^{L}p_\theta(z_\ell\mid h,c,z_{<\ell}).$$

搜索短码后仍需映射目录、处理冲突与资格，因而没有凭公式消除所有截断。另一条路线先生成连续偏好向量，再接目录检索；还有方法只生成训练样本，最终继续用传统推荐器打分。[DMT综述§1–2](../../来源/SRC-GENREC-DMT/阅读笔记.md#从匹配到生成究竟改变哪一步)提供这些研究动机，[LongTalk对照](../../来源/SRC-GENREC-LONGTALK/阅读笔记.md)强调从原系统限制和强基线出发。

世界知识来自预训练与输入信息，规模收益依赖数据、架构和计算。行为原生生成器不因输出Token就获得语言常识，传统推荐也可使用文本和外部知识。研究目标应落在具体缺口，不能由“范式革新”推出普遍优越性。

## 数据—模型—任务是交叉框架

[DMT综述](../../来源/SRC-GENREC-DMT/阅读笔记.md)采用广义定义：推荐任一阶段使用生成模型即纳入范围。数据、模型、任务描述不同设计轴；LLM、推荐原生大型模型（LRM）与扩散也可以相互结合。

| 观察轴 | 要确定什么 | 深入入口 |
|---|---|---|
| 数据 | 生成内容、表征、交互还是有状态轨迹；统一域、任务、模态还是参数 | [数据与标签](../模块/数据、样本与标签.md)、[合成反馈](../问题/生成数据怎样补充真实推荐反馈.md) |
| 表示与生成接口 | 输入是文本、行为向量或码；输出是物品码、连续查询、列表或内容 | [表征编码](../模块/表征与物品编码.md)、[生成机制](../模块/生成机制与约束解码.md) |
| 学习信号 | 日志似然、对比、排序、代理奖励、真实反馈或教师概率 | [训练与对齐](../模块/训练目标与偏好对齐.md)、[偏好比较](../问题/生成式推荐怎样从似然训练走向偏好对齐.md) |
| 任务与系统 | 解决Top-K、内容、解释、对话或推理；具体替换哪一阶段 | [输出与评估](../问题/生成式推荐怎样选择输出对象与评估目标.md)、[级联衔接](../模块/粗排与级联衔接.md) |
| 验证与部署 | 映射后的结果、真实收益、更新路径和整链路预算 | [评估](../模块/评估、偏差与因果收益.md)、[服务效率](../模块/在线服务、更新与计算效率.md) |

例如，LLM写商品描述后由SASRec排序，改变的是数据；TIGER生成语义码，改变候选产生；PENS写个性化新闻标题，改变展示内容。三个任务不能放进一个命中率排行榜。[Gen-RecSys综述](../../来源/SRC-GENRECSYS-REVIEW/阅读笔记.md)补充生成模型家族、RAG和多模态视角；两篇综述都提供组织框架，没有统一重训的效果排名。

## 数据侧：合成反馈与统一信息分别设计

内容增强补描述或意图，表征增强提供向量，行为增强写入伪交互，图增强改变传播边；它们分别改变输入信息、监督分布和拓扑。合成样本应保留来源及生成时可见时间，用独立真实数据验收，不能把生成标签数量当成新增真实曝光。

[ColdLLM](../../来源/SRC-COLDLLM/阅读笔记.md)以过滤—细化为冷物品补伪交互，再接入下游推荐；[Agent4Rec](../../来源/SRC-AGENT4REC/阅读笔记.md)以画像、记忆、动作和环境构造有状态模拟。前者重点是冷物品注入的质量与代价，后者重点是模拟能否预测策略改变后的真实响应。拟人化对话、模拟满意度与真实用户收益是不同证据，Agent模拟不自动替代在线A/B。ColdLLM面向冷物品，综述的“冷启动用户”转述应按原论文纠正。[机制与比较](../问题/生成数据怎样补充真实推荐反馈.md)。

统一输入格式以后，身份、分布和任务差异仍存在。[FedCGR](../../来源/SRC-FEDCGR/阅读笔记.md)在行为留本地的条件下共享语义接口和部分参数，以私有CF残差及原型聚合处理域差异；[UniGCRec](../../来源/SRC-UNIGCREC/阅读笔记.md)在中心可访问多域行为的条件下先筛选源域证据，再形成离散用户条件。两者的访问边界不同，不能当作同信息条件下的替代排名。原始行为不上传也不等于差分隐私；软门不能保证每个域都没有负迁移。[跨域模块](../模块/多场景、迁移与冷启动.md)将两者与STAR、PLE、PEPNet按共享对象比较。

## 表示侧：同叫Token，职责可能完全不同

| 对象 | 代表机制 | 输入、输出与映射边界 |
|---|---|---|
| 物品码 | [TIGER / LC-Rec / LETTER](../问题/用语义短码直接检索物品.md) | 内容量化、语言协同对齐或可学习协同码；生成后寻址既有实体，须检查冲突和更新 |
| 用户码 | [UniGCRec](../../来源/SRC-UNIGCREC/阅读笔记.md) | 跨域证据压成条件前缀；用户/物品有各自RQ-VAE和码本，分别跨域共享，同整数不代表同语义 |
| 连续行为输入 | [LLaRA](../问题/如何用语言接口统一个性化推荐任务.md#llara用连续行为位置补充文本提示) | 冻结推荐器的物品向量经投影进入LLM提示；最终生成候选标题，仍需名称匹配 |
| 连续检索查询 | [TokenRec](../../来源/SRC-TOKENREC/阅读笔记.md) | 离散协同码输入LLM，输出连续查询，再对目录协同向量检索；输入离散不等于输出物品码 |
| 内部潜状态 | [LatentR³](../问题/推荐潜推理怎样从答案反馈中学习.md) | 当前LLM隐藏状态形成可训练连续中间输入，不是稳定物品地址 |
| 外部预测输入 | [OneReason](../../来源/SRC-ONEREASON/阅读笔记.md) | 在线快模型的Thinking Token承载外部预测Embedding，与内部连续潜状态来源不同 |

编码质量、生成质量与目录映射需要分别检查。组合空间大不证明实际零碰撞，合法码不保证一物一码、实时库存或足额去重K项；已有文本内容的新物品、未见ID、未见用户与完全无历史也有不同条件。[编码模块](../模块/表征与物品编码.md)集中解释这些边界，量化基础和工程建议可接[GRID实践手册](../../来源/SRC-GRID-PAPER/阅读笔记.md)。

[LIGER](../问题/生成候选怎样结合连续检索与冷启动.md)提供另一种混合接口：先生成候选，再补入整个冷物品集合，最后用连续文本表征排序。冷物品绕过的是生成概率门槛，是否命中仍取决于排序和候选竞争；收益与额外扫描成本都依赖冷池大小，不能解释为码生成器单独学会了全部冷物品。

## 模型侧：按实际生成对象比较

预训练LLM适配借助语言先验，推荐原生大型模型从行为数据和推荐计算出发，扩散以多轮恢复生成向量或码。模型类别不决定系统输出：HSTU做候选条件响应预测，OneRec V1生成整会话码序列，OneRec-V2按目标物品的三个SID组织解码。[HSTU机制](../问题/序列怎样统一候选条件预测.md)、[列表依赖](../问题/列表顺序与前缀依赖怎样建模.md)和[目标解码计算](../问题/生成推荐怎样把计算集中到目标解码.md)分别展开。

| 生成对象 | 路线 | 推理怎样得到结果 |
|---|---|---|
| 全目录交互分数 | DiffRec；L-DiffRec在压缩空间恢复 | 从历史扰动开始，多步去噪后解码全目录并排序 |
| 连续下一物品表示 | DreamRec、PreferDiff | 从Gaussian噪声条件生成，再做目录内积检索 |
| 离散目标码 | TIGER、LC-Rec、OneRec-V2等 | 逐Token搜索合法路径，再映射实体 |
| 离散掩码补全 | MDGR | 全掩码起步，按置信度分轮补码和组合搜索，再映射目录 |
| 整会话码序列 | OneRec V1 | 后一物品依赖前面已生成物品，与逐独立目标不同 |
| 查询文本 | OneSug | 为搜索前缀生成建议，再进入商品搜索链路 |
| 新展示标题 | PENS | 给定新闻正文和兴趣，生成个性化标题，新闻实体已给定 |

[扩散比较](../问题/交互向量怎样通过去噪生成推荐.md)解释前三种扩散接口的监督、初态、映射和成本。MDGR少几轮前向可能增加组合搜索，DreamRec/PreferDiff仍需目录检索；“并行”不能单独证明更低延迟。OneSug的RQ-VAE负责参考检索，输出仍是开放查询文本；LLaRA的标题用于候选寻址，PENS的标题用于展示，不能因都输出文字就共用一套正确性定义。[输出评估](../问题/生成式推荐怎样选择输出对象与评估目标.md)。

## 训练侧：先确定反馈来自哪里

下一Token似然拟合观测目标，表示对比帮助空间对齐，课程改变样本或掩码难度；这些目标本身不新增真人偏好。LETTER的温度化NLL、LLaRA的提示课程与UniGCRec的对比对齐加目标NLL，分别控制编码/生成、输入形式和跨域条件，不应一概称作偏好强化学习。

偏好与奖励方法还需对齐监督单位。以下依据各自固定版本，详细公式、实现差异和原文疑点见[偏好问题](../问题/生成式推荐怎样从似然训练走向偏好对齐.md)。

| 方法 | 反馈单位与来源 | 不能直接替代什么 |
|---|---|---|
| OneRec V1 IPA | RM比较生成会话，逐轮更新参考快照 | 代理列表奖励不是未曝光列表的真实反事实反馈 |
| S-DPO | 一正多负候选标题相对SFT参考的部分排序 | 随机负例不是已观测拒绝，全库检索需另验 |
| OneRec-V2 GBPO | 长度桶观看分位与负反馈构造目标物品优势 | 概率基线不是日志曝光propensity |
| OneMall | 线上精排器给生成物品SID评分 | 排序代理改善不证明全部级联可取消 |
| OneSug | 查询行为等级构造偏好并保留SFT | 一正多负“列表损失”不等于整列表联合生成 |
| PreferDiff | 正物品与批内负质心的恢复误差差 | 实际混合损失不是无条件的标准DPO |
| LatentR³ | teacher forcing下答案负PPL评价潜状态 | 奖励改善不直接证明自由生成名次或推理忠实性 |
| OneRec-Think | 理由后beam候选与单一目标的最大码匹配数 | 多候选不等于多个人类确认的正例 |
| OneReason | 命中乘首级码覆盖；RFT/MOPD整合专家 | 首码覆盖不是实际品类多样性，教师概率不是新增用户标签 |

显式理由监督还要说明教师是否看到训练目标。OneRec-Think与OneReason使用目标条件合成，这本身不等于测试泄漏，也不证明理由就是用户真实动机。训练/测试隔离、答案暗示、等预算直接答案对照和理由干预需要分别核验。[推理机制与比较](../问题/推荐潜推理怎样从答案反馈中学习.md)。

## 服务与级联：生成以后还有哪些工作

[OneMall](../../来源/SRC-ONEMALL/阅读笔记.md)把精排预测奖励注入生成召回；[OneSug](../问题/短前缀怎样生成相关且有排序能力的查询建议.md)替代查询建议级联；[OneRec-V2](../问题/生成推荐怎样把计算集中到目标解码.md)集中计算于目标解码。三个系统替代范围不同，不能统一称作“终结召排”。完整分工见[级联模块](../模块/粗排与级联衔接.md)。

缓存也有不同对象：HSTU的M-FALCON复用候选间历史计算；OneRec-V2共享历史K/V；OneRec-Think的Think-Ahead离线缓存两级候选前缀，实时模型补末级码；OneReason近线可缓存完整候选，并以外部预测增强在线快模型。缓存命中、刷新、覆盖新兴趣和回退必须与命中率一起计量，不能把离线推理移出在线路径后视为总成本消失。[服务模块](../模块/在线服务、更新与计算效率.md)。

实际预算包括画像/教师调用、编码与码本训练、主模型训练、候选搜索、目录索引、过滤补位、缓存存储和刷新。UniGCRec的LoRA适配对照不覆盖全部阶段，较少激活参数也不是请求总成本；AtSpeed的验证加速依赖接受率及目标搜索设置。[多物品解码加速](../问题/多物品生成怎样减少串行模型调用.md)与[目标历史复用](../问题/目标感知排序怎样复用历史计算.md)提供不同层次的依据。

## 评估：在输出实际被使用的位置验收

物品推荐首先固定目录、可见信息、时间、候选、K和过滤规则，比较映射后的全请求结果，同时报告失败、重复和补位。LLaRA代码中的有效子集HR乘有效率才对应全请求HR；OneMall的teacher forcing码准确率、回放候选命中与线上收益也是三种证据。[输出评估问题](../问题/生成式推荐怎样选择输出对象与评估目标.md)给出定义和例子。

| 要验证的主张 | 适合的证据 | 常见越界 |
|---|---|---|
| 合成数据有用 | 生成来源/时间可追溯的真实留出对照 | 用合成标签或生成器自评作最终真值 |
| 更好地选择物品 | 同任务、候选与预算的Recall/NDCG/HR及最终合法K项 | 全库与抽样候选、条件HR与全请求HR混比 |
| 能跨域或冷启动 | 明确身份、训练覆盖、逐域收益与跨域全局时间 | 零重合等同零历史/无身份关联；内容码未见等同ID未见 |
| 内容与理由可信 | 独立事实评价、条件符合、理由干预和真人评价 | ROUGE、参考链相似或历史引用率当作忠实性 |
| 真实用户受益 | 披露随机化、周期、流量、区间及副作用的线上试验 | RM分数、仿真满意度或离线命中当作业务因果收益 |
| 更省资源 | 同负载下整链路时延分位、吞吐、资源及更新 | 少Token、少轮次、参数减少直接换算为P99收益 |

UniGCRec的零重合实验仍须确认身份归属、保留样本与逐前缀画像时间，不能据协议缺项直接断言测试泄漏。PENS的个人参考ROUGE不能替代生成标题的事实与阅读收益；Agent4Rec的模拟反馈也需要真人校准。[评估模块](../模块/评估、偏差与因果收益.md)统一展开协议，经典基础接[任务与指标](../问题/推荐任务怎样决定评估指标.md)和[候选采样](../问题/采样候选为何改变排序指标与模型次序.md)。
