# 持久知识层

反复研究一个主题时，逐篇摘要很容易保存，跨论文的理解却容易散落在聊天里。下一次再问同一问题，仍要重新拼接术语、假设和实验条件。持久知识层把这些已经完成的综合保存为可修订的文章，让后续阅读从已有理解继续。

## 原件、知识与组织规则

Karpathy 在《LLM Wiki》的 The core idea / Architecture 中提出，在原始资料与查询之间维护一层持续更新的 Wiki。新资料不仅产生摘要，还会修改既有主题、概念与冲突记录；有价值的问答也可以回写。这是一个知识组织模式，原文没有给出检索准确率或推荐效果的受控实验。见 [原文与版本](../../来源/SRC-KARPATHY/阅读笔记.md)。

三层承担不同职责：

| 层 | 保存什么 | 为什么需要 |
|---|---|---|
| 原始资料 | 论文、源码、报告的固定版本 | 为数字、公式和具体陈述提供可回查依据 |
| 持续知识 | 定义、机制、方法比较、适用条件与未解分歧 | 复用已经形成的理解，并接受新证据修订 |
| 组织规则 | 页面结构、引用要求、更新约定 | 让不同时间的新增内容能合并到同一知识体系 |

原件固定，理解可以变化。若新论文推翻了旧解释，应修改知识页，并保留结论改变的原因；原论文仍是历史证据。

## 从论文笔记走向问题文章

论文笔记沿一篇论文展开：它为什么提出这个问题，结构如何设计，训练和推理怎样进行，实验支持了什么。问题文章沿一个问题展开：它有哪些解法，各自依赖什么条件，机制和成本有何差别。

例如，学习某类推荐模型的推理效率，可以在论文笔记中解释该论文的具体计算过程，在问题页中比较各方案改变了哪个计算环节、付出什么训练或存储代价，再链接回相应论文。这个例子说明组织方式，不预设任何算法结论。

一篇新论文可能只给已有问题补充一种解法，无需另建整套概念页。本地 llm-wiki skill 的 Before Updating / Update Chain 要求先搜索、优先更新已有页面；其 Auto-Sync 排除临时进度与重复内容。这能减少“同一个问题有很多份互不相通的摘要”。见 [维护流程来源](../../来源/SRC-LOCAL-SKILL/阅读笔记.md)。

## 累积理解的边界

持久知识保存的是当前解释，并不增加原始证据的数量。两篇综合转述同一实验，仍只有一份实验依据；新资料到来后，旧比较也可能需要重写。关键结论应遵守 [证据与适用范围](证据与适用范围.md)，更新关系见 [知识维护](../综合/知识维护闭环.md)。

这种组织适合持续学习、跨资料比较和反复纠错。一次性查询未必需要建页；词面检索、向量检索都可以帮助查找，维护 Wiki 本身不保证更高准确率或更低总成本。
