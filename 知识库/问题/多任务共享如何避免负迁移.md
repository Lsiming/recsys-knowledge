# 多任务共享如何避免负迁移：专家分工、渐进路由与监督边界

联合预测点击、完成比例或分享，可以用多种反馈帮助同一套表示，也会让不同目标争夺参数。关键问题不只是损失配多大权重，还包括：哪些任务能读取哪些表示、哪些梯度能流回哪些参数。PLE用共享与专有专家区分连接，再让低层信息通过共享分支交换，在高层逐渐分开任务。它提供的是减少有害干扰的结构先验，不能保证任意任务组合都优于单任务。

## 先把负迁移变成可比较的问题

至少要有对应单任务基线，固定标签、训练样本、切分与相近结构。PLE定义的MTL gain为：AUC等越大越好时，$M_{MTL}-M_{single}$；MSE等越小越好时，$M_{single}-M_{MTL}$。某些任务正增益、另一些负增益是其“跷跷板”现象，而非任意训练波动。绝对指标差不能当成相对提升百分比。[PLE精读](../../来源/SRC-PLE/阅读笔记.md#跷跷板相对于谁发生)；[出版方全文入口（原文式(11)，PDF第7页；需按标注位置查找）](https://doi.org/10.1145/3383313.3412236)。

任务相关系数也不能直接决定是否共享。有效观看标签依赖播放与观看时长，自动播放又改变播放分布，样本不同关系不同。若只有一个固定共享强度，即便平均相关性高，也可能对部分样本有害；这是PLE视频场景的动机，不是已经证明所有任务都满足的规律。

## 结构决定哪些专家能被谁选择

下表的MMOE、ML-MMOE、cross-stitch与sluice机制依据**PLE一篇论文的结构描述与内部对照**，没有把它们当作独立原文精读；MMOE原文仍未取得。

| 方案 | 表示与融合 | 梯度路径及主要取舍 |
|---|---|---|
| 硬共享底座 | 全部任务使用同一底层表示，各有预测塔 | 结构简单；任务梯度直接共同更新底座，专有模式可能相互干扰 |
| 本篇cross-stitch/sluice对照 | 静态线性权重融合任务表示 | 可学跨任务组合，但同一组权重用于所有样本，缺少输入相关选择 |
| 本篇MMOE对照 | 同一专家池，各任务门根据输入加权 | 能按样本、任务调整组合；全部专家仍可受到各任务影响 |
| CGC | 每任务只读自身专有专家和共享专家 | 显式排除对其他专有专家的直接连接；早期分离可能限制深层共享 |
| PLE | 多层任务分支、共享分支；共享门读取全体专家 | 低层经共享路径交换信息，高层逐步分离；增加专家与门的计算、容量和调参 |

单层CGC可写为：

$$g_k(x)=\sum_{r=1}^{m_k}a_{k,r}(x)E_{k,r}(x)+\sum_{r=1}^{m_s}b_{k,r}(x)E_{s,r}(x),\qquad\hat y_k=t_k(g_k(x)).$$

$E_{k,r}$为任务$k$专有专家，$E_{s,r}$为共享专家，$m_k,m_s$为数量；$a,b$由同一个线性门的Softmax产生，共同归一化。输入$x$既供专家计算也作selector。它改变了允许连接的集合，并不保证所有专家形成语义纯粹的分工。[机制与符号](../../来源/SRC-PLE/阅读笔记.md#cgc把允许共享的连接写入结构)；[出版方全文入口（原文式(2)–(5)、图4，PDF第5页；需按标注位置查找）](https://doi.org/10.1145/3383313.3412236)。

PLE在每层另加共享门，把全部任务专家与共享专家组合为下一层共享表示。高层门用下层对应融合结果作selector。最后各任务形成自己的表示并进入塔；图5末层没有为不存在的下一层再输出共享表示。[出版方全文入口（原文式(6)–(7)、图5，PDF第6页；需按标注位置查找）](https://doi.org/10.1145/3383313.3412236)。

一个关键后果是：低层A专有专家→共享门→高层共享专家→B任务塔是一条可能路径。因此B损失能影响低层A专有专家；“专有”不等于所有层的梯度完全隔离。CGC的单层隔离与PLE的渐进分离是两种取舍，不能混讲。[两层路径解释](../../来源/SRC-PLE/阅读笔记.md#ple让低层信息经过共享分支再回到任务)。

这些门都按Softmax密集融合；本文没有稀疏Top-K执行或端到端省算力证据。层数相等不代表参数/FLOPS相等，门权重非零也不能证明MMOE永远学不到近似有效分工。模型选择应同时看逐任务增益、资源与调参成本，不能仅凭结构名称排序。

## 共享结构不代替标签空间与业务决策

PLE的任务损失采用有效样本掩码：

$$L=\sum_k\omega_kL_k,\qquad L_k=\frac{\sum_i\delta_k^i\,loss_k(\hat y_k^i,y_k^i)}{\sum_i\delta_k^i}.$$

$\delta_k^i$表示样本$i$是否属于任务$k$的监督空间。无有效标签的样本不进入该任务损失，不是被自动标成负例。训练权重采用预设指数计划$\omega_k^{(t)}=\omega_{k,0}\gamma_k^t$，并不根据实际梯度冲突自适应，原文step/epoch单位尚有歧义。[出版方全文入口（PLE原文式(8)–(10)，PDF第7页；需按标注位置查找）](https://doi.org/10.1145/3383313.3412236)。

[ESMM](../../来源/SRC-ESMM/阅读笔记.md)解决的是相邻但不同的问题：给定“转化必先点击”，以$P(C\cap V\mid x)=P(C\mid x)P(V\mid C,x)$，在全曝光监督CTR与CTCVR，间接学习CVR，同时共享Embedding。PLE的mask只是确定哪些损失有定义，不能直接产生ESMM的联合事件约束或一般性无偏估计；ESMM的概率恒等式也不自动决定最佳专家共享方式。[点击后转化率问题](点击后转化率估计.md#esmm用可观测任务约束-cvr)。

最后，训练权重与排序权重不同。PLE系统将预测以带指数的乘积、再结合视频长度函数排序，权重通过线上实验搜索；多个预测头的联合学习不自动给出用户效用、预算约束或Pareto选择。这一层由[多任务学习与多目标决策](../模块/多任务学习与多目标决策.md)继续组织。

## 现有证据支持哪些选择

在Tencent News连续8天、0.995十亿样本中，前7天训练、末天测试；VTR用AUC、VCR用MSE。表1单任务为0.6787/0.1321，MMOE 0.6803/0.1319，CGC 0.6832/0.1320，PLE 0.6831/0.1307。CGC主要提高VTR，PLE改善VCR且维持接近的VTR；PLE并非逐项最高。没有置信区间、完整超参数预算或参数量匹配信息，不据0.0001差推导普遍优劣。[实验设置及表1](../../来源/SRC-PLE/阅读笔记.md#工业结果支持联合改善但不是逐项永远最优)。

4周按用户随机分桶的线上实验，PLE相对单任务每用户总观看次数+4.17%、总观看时长+3.57%；MMOE为+1.94%/+1.73%。两组提升率相差2.23/1.84个百分点；真正以MMOE为分母的相对差约2.19%/1.81%。此结果支持特定腾讯系统中的实际收益，不等于任意推荐任务都能获得相同收益。[线上口径](../../来源/SRC-PLE/阅读笔记.md#线上数字要先还原共同基准)；[出版方全文入口（原文表3，PDF第8页；需按标注位置查找）](https://doi.org/10.1145/3383313.3412236)。

公开数据和多任务组补充了任务关系变化的证据，但原文表5的Census任务1中MMOE AUC与gain明确冲突，表2正文“除cross-stitch均正增益”也与ML-MMOE的负值不符。这些局部结果应保留疑点，不能据它们建立严格优越性证明；详见[精读的证据边界](../../来源/SRC-PLE/阅读笔记.md#公共基准与门权重图的证据边界)和[审核台](../../维护/审核台.md)。当前没有本仓库复现实验。

相邻的多域问题采用另一种共享粒度：[STAR的条件归一化与权重调制](多场景怎样共享模型又保留差异.md#与ple的分界在参数调制还是表示选择)保留同一点击标签，按域改变统计和有效参数；PLE按任务、输入组合专家表示。两者的共享路径均可能传递跨目标或跨域影响，不能用“专有”一词代替梯度分析，也不能跨论文协议按AUC排名。
