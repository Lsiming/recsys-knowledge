# 稀疏 ID 哈希何时会共享参数

一次曝光样本里有用户 ID、物品 ID 或离散交叉键。不断增长的字典和逐键参数表会吃掉内存，但取模后的整数可能同时用来做三件事。先沿一样本判断这个整数最终索引的是输入坐标、一行共享参数，还是持有完整键的机器。

## 一次碰撞怎样进入分数和梯度

设两个键 $A,B$ 的特征值分别为 $2,1$，都落入桶 3。有符号特征哈希把 $x$ 映入 $m$ 维稀疏向量。独立的符号哈希 $\xi$ 若给 $A$ 取 $+1$、$B$ 取 $-1$，则 $\phi_3(x)=2-1=1$。线性分数使用 $w_3\phi_3(x)$。若损失为 $\ell$，桶权重收到梯度 $(\partial\ell/\partial z)\phi_3(x)$，其中 $z$ 是线性分数。两键恰好等量异号时，这个样本给该桶的线性梯度为零。

对另一样本 $x'$，有
$$
\langle\phi(x),\phi(x')\rangle
=\sum_j x_jx_j'
+\sum_{i\ne j}\mathbf 1[h(i)=h(j)]\,\xi(i)\xi(j)x_ix_j'.
$$
第一项是原内积，第二项是碰撞误差。对随机映射取期望时，第二项里的不同键符号乘积均值为零。若某次部署固定了种子，一对键发生的碰撞随该版本保持不变。方差量级随桶数增大而降低，误差大小还受各键在样本中的位置和值影响。只激活不同坐标的两个单位 one-hot 向量，原内积为 0。若哈希均匀且符号独立，以 $1/m$ 的概率同桶，此时压缩后的内积为 $+1$ 或 $-1$，两者等可能。其均值为 0、方差为 $1/m$。增桶降低这对键发生串扰的概率，同桶时的误差绝对值仍为 1。固定映射下可以直接检查哪些高影响键共享了桶。[Feature Hashing v4 §2–3，式 (2)–(3) 和引理 2，第 2 页](https://arxiv.org/pdf/0902.2206v4#page=2)。

| 用法 | 两键哈希值都为 3 后的状态 | 一次监督怎样更新 |
|---|---|---|
| 有符号稀疏输入 | 在坐标 3 做带符号加和 | 通过合并后的输入更新线性权重 $w_3$ |
| 共享 Embedding 桶表 | 两键都读取同一行 $E_3$ | 两个读出位置返回的向量梯度累加到同一行 |
| 完整键的分布式表 | 两键都由分片 3 服务，内部键仍是 $A$ 或 $B$ | 发往同一个分片，各自更新 $E_A,E_B$ |

共享 Embedding 的两个键会长期影响同一向量；是否值得共享取决于两个键的语义、热度和监督是否近似。如果使用完整键索引，路由哈希碰撞仍会集中负载，但参数语义保持独立。在同一个系统中，桶化可以先规定模型参数的键，第二次哈希再决定这些键归哪个分片。训练与服务必须对齐相同字段命名空间、哈希算法和种子，换映射后旧参数会被新的键读出。

## 桶数应该沿错误最集中的样本检查

论文的邮件任务把全局词与用户专属词都映射到同一权重向量。在 1% 的正常邮件误报率下，22 位桶表的个性化模型相对 26 位桶表的全局基线漏判量约为 0.70。这个结果检验了一个任务与数据切分中的内存和效果折衷；监督稠密度、桶热度和损失都会影响其他任务的最优桶数。推荐场景里可在同一时间切分与预算下，分别比较头部共桶键、跨字段同名键、低频及新键的覆盖、分数漂移和排序指标。若只把完整键改路由，则更关心分片访问分布、排队和尾延迟。[Feature Hashing v4 图 2–3，第 5 页](https://arxiv.org/pdf/0902.2206v4#page=5) · [实验口径详解](../../来源/SRC-FEATURE-HASHING/阅读笔记.md#桶数是在内存与干扰之间做选择) · [完整键怎样在分片中读写](稀疏参数分布式训练怎样控制读写陈旧.md)。

工业点击预估提供了另一种结果。McMahan 等尝试对生产广告模型做特征哈希，在其测试中把坐标压到数十亿以下就观察到损失，因此保留了可解释的未哈希特征。两篇论文的任务与特征分布不同。邮件任务对照的是个性化和全局分类器在固定误报率下的漏判量，CTR 系统试的是继续压缩现有特征表。可把选桶与 FTRL 置零分开比较：哈希先决定两个特征是否共用坐标，FTRL 的 $L_1$ 阈值随后决定该坐标的权重是否为零。[McMahan 等 §9.1，第 8 页](https://chbrown.github.io/kdd-2013-usb/kdd/p1222.pdf#page=8) · [FTRL 逐坐标更新](在线CTR怎样得到稀疏权重.md)。
