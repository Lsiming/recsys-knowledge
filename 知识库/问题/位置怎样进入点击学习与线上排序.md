# 位置怎样进入点击学习与线上排序

精排收到候选时，实际展示位置还没确定。日志点击则是旧策略已排序、用户有机会查看之后的反馈。如果同一类候选过去大多排在首屏，离线高点击可能来自位置优势。把真实位置拼进模型能描述历史曝光条件，服务前为所有候选补一个固定位置时，模型里的位置与物品交互仍可能改写候选次序。

## 排序前只给候选打条件分数

PAL 将日志点击概率分成 $P(\mathrm{seen}\mid j)$ 和 $P(y=1\mid x,\mathrm{seen})$，前者只吃位置，后者吃用户、物品与上下文。训练用乘积和点击标签算交叉熵。排序时取后者，因为服务尚未确定 $j$。同样两个候选，如果条件分数为 0.20 和 0.12，各自在历史位置的查看概率为 0.30 和 0.80，则已曝光点击估计是 0.06 和 0.096，排序分数却是 0.20 和 0.12。若业务要估计特定位置的曝光点击概率，可[按分数分桶校验相乘后的概率](排序分数怎样校准为曝光点击概率.md#位置已知时哪一个分数对应观察点击率)。[PAL §2、图 3](../../来源/SRC-PAL/阅读笔记.md#从真实位置构造训练样本)

位置分支的解释依赖分离假设，尤其是关注率只随位置变化。点击标签约束乘积，在概率范围允许时可以让位置分支乘一常数、另一个分支除以该常数。两者各自的绝对概率在这种情况下缺少锚定。列表布局、同屏内容和旧模型的强选择都可能让真实查看过程偏离模型。这里有两种容易混用的概率。PAL 的 $a(j)$ 描述排到 $j$ 后被用户看见的机会。随机交换实验中，系统把一个候选放到 $j$ 的概率来自分流设计。举例说，两种顺序以各一半概率展示，首位的查看率仍可能高于次位。若要回放一个会更换整张列表的策略，还要检查日志能否展示目标列表，以及实际如何分配这些列表。[PAL 式 (2)，出版页 453](https://doi.org/10.1145/3298689.3347033) · [随机日志回放的动作单位](上下文探索怎样平衡并用随机日志评估.md#回放整张列表时要匹配哪个动作)

## 离线点击指标和新策略线上反馈各有观察对象

换模型前先核全库或抽样候选、同一时间切分、列位置和用户分组，明确 AUC 是把全体曝光混合计算还是先在用户或请求内计算。一个模型在旧候选及可见位置上的离线提升，可能无法覆盖上线后新增、替换或下移的物品。PAL 的下一日离线日志测试没有在 AUC 或 LogLoss 上胜过全部缺省位置设置，但其线上对照报告了下载相关指标的提升。线上结果应同时保留曝光与用户两个分母，并记录每个时间段使用的基线及实际分流。[PAL §3](../../来源/SRC-PAL/阅读笔记.md#在线对照测的是排序策略的真实下载结果) · [分流与交互](线上实验怎样复用流量并识别真实增量.md)
