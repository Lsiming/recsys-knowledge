# 统一框架下怎样保持实验协议可比

推荐算法共用一个训练脚本，仍可能在回答不同问题：一个测试随机留下的交互，另一个预测未来；一个从一百件抽样物品选择，另一个在全物品排序。可比性首先取决于观察对象与候选空间，再讨论模型结构和指标高低。

RecBole统一数据表示和公共执行过程，同时暴露协议选择。它提供比较条件的控制点，不能仅凭框架名确认公平。下述机制来自2021年论文，不承诺当前接口相同，完整证据见[RecBole精读](../../来源/SRC-RECBOLE-PAPER/阅读笔记.md)。

## 复用数据表示后，还要固定可见信息

RecBole将输入变为原子文件，经Dataset预处理，再由DataLoader生成按特征名索引的批张量Interaction。交互、侧特征和图谱输入可以组合复用，减少重复实现。[论文§2.1、表2–5](https://arxiv.org/pdf/2011.01731v3#page=3)包括过滤、ID映射、填补、标签生成与归一化功能。

同一原始文件不意味着同一训练数据。例如用全部时间的交互次数过滤再时间切分，与只用训练期统计过滤，会定义不同人群与可用信息；这是协议分析示例，并非断言RecBole实际发生泄漏。特征也应按预测时点核可用性，存进同一Interaction不能保证信息合法。

## 排序、切分与候选共同定义评估问题

[论文§2.3.2、表7](https://arxiv.org/pdf/2011.01731v3#page=6)分为Group、Split、Order、NegSample。随机/时间排序与比例/留一切分组合，评估另选full或uniN（一正例加N负例）。

| 比较维度 | 常见选择 | 实质差别 |
|---|---|---|
| 切分前顺序 | 随机 / 时间 | 随机留下行为与预测未来的上下文不同 |
| 切分方式 | 比例 / 留一 | 测试正例数、人群覆盖与历史长度可变 |
| 时间边界 | 用户内 / 全局时点 | 用户内最后事件可能跨越他人训练时间 |
| 候选空间 | 全物品 / 抽样 | 竞争数量与分布不同，同名指标不直接排名 |
| 已见物品 | 屏蔽 / 保留 | 允许重复推荐与否改变可行答案 |
| 模型选择 | 调参范围、预算、早停、seed | 结果也受选择过程影响，须连协议报告 |

接口让差异可配置、可记录，论文明确不替用户选最合适协议。其引用的抽样指标研究未在本批取得原文，不能借二手引用补造定量结论。

[BPR](隐式反馈的相对偏好学习.md)、[SASRec](从历史顺序预测下一物品.md)与[LightGCN](利用交互图传播协同表示.md)不能只按模型名与NDCG高低比较：先明确能看见什么、从哪些候选给谁预测，再对齐目标与资源。

## GPU批量评估优化计算方式，不改变评估目标

给定n位用户、m件物品的分数矩阵D，将排除物品分数设负无穷，用GPU topk产生n×K索引A。测试正例矩阵B记录用户—物品命中，再按A收集n×K二值矩阵C计算指标。可将操作写为：

$$
C_{u,k}=\mathbf{1}[A_{u,k}\in T_u],
$$

T_u为用户u的测试正例集。按批执行topk与gather，减少逐用户处理。[论文§2.3.3、图2](https://arxiv.org/pdf/2011.01731v3#page=7)中抽样评估仍构造n×m稠密分数矩阵，未说明稀疏压缩；O(nm)存储需以batch控制。

表8在BPR、MovieLens与RTX3090条件下报告显著加速，见[精读实验](../../来源/SRC-RECBOLE-PAPER/阅读笔记.md#表8支持特定评估实现加速计时边界仍有缺口)。没有分项消融，列表生成和指标计算的计时描述也不完全一致。这支持特定离线评估优化，不证明减少模型打分成本，不能替代[在线计算预算](../模块/在线服务、更新与计算效率.md)中的索引、解码和服务延迟评估。

评分误差、排序命中与业务干预分别回答不同问题，统一离线框架不能替代[评估模块](../模块/评估、偏差与因果收益.md)讨论的随机实验与因果识别。
