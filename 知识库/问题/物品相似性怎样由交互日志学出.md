# 物品相似性怎样由交互日志学出

以耳机 A、耳机套 B、降噪耳机 C 为例。用户甲有 A→B 的点击，用户乙有 B→C 的点击。这两段行为至少支持 A 与 B、B 与 C 有关系。A 与 C 是否也相似，取决于模型如何定义确认过的邻居、怎样跨用户共享信息，以及希望召回的是配件还是另一款耳机。

## 评分预测与隐式排序使用不同监督

ItemCF 用两列共同有效的用户评分衡量物品关系。调整余弦先减去同一用户的历史平均评分，避免两列同时高分仅仅来自用户习惯打高分。预测 C 时，把当前用户对 C 的若干物品邻居的已有评分加权。服务提前保存物品邻域，在线遍历用户历史或查已知目标的邻居。隐式点击日志没有评分中心化所需的分值。常见二元共现计数可视为相似性设计的另一种输入，使用它时要单独定义用户、时间窗与流行度归一化。[ItemCF 原文精读](../../来源/SRC-ITEMCF/阅读笔记.md)。

BPR-kNN 保留历史相似度求和这一接口。对甲，用已点过的 A 与目录未交互的 C 构造 A>C 的教学约束，评分项利用甲其余已交互物品。对乙已有的 C，训练可能将它推到另一些未交互物品之前。未观测的位置只为构造个体内排序对提供假设。原文在随机留一 AUC 下与余弦 kNN 比较，评分 MAE 来自 ItemCF 的另一个任务。[相对偏好问题](隐式反馈的相对偏好学习.md)。

## 集合、会话和图分别定义什么是邻居

将甲和乙的历史视作两个集合，Item2Vec 训练 A→B、B→A、B→C、C→B 四个方向性正对。在小维向量表中，中心 A 与中心 C 共享上下文 B，两者可能因共享更多相似上下文而在余弦空间相近。若三个物品在同一购物篮，论文的全窗口还会直接训练 A→C 和 C→A。服务可以只使用种子物品与中心向量表。基础损失、从文本窗口到物品集合的变化见 [Word2Vec NEG](../../来源/SRC-WORD2VEC-NEG/阅读笔记.md) 与 [Item2Vec](../../来源/SRC-ITEM2VEC/阅读笔记.md)。

Airbnb 给每个点击保留有序窗口，且在已预订会话中让窗口里的中心都预测最终预订。用同城市负例迫使模型区分别的房源。这样可以用实时点击快速形成当前行程的偏好，用用户与房源类型补充跨行程偏好。[Airbnb 原文精读](../../来源/SRC-AIRBNB-EMBEDDINGS/阅读笔记.md)。

EGES 先把 A→B 和 B→C 记作有向边，再按出边权重游走得到 A、B、C。窗口覆盖两跳时，即使 A、C 没有在同一会话，它们也会构成训练监督。中心向量是按物品学习的 ID 和属性嵌入加权平均，冷启动时对可用侧信息向量等权平均。游走策略、训练窗口、属性质量及可用时间会共同改变邻域。[EGES 原文精读](../../来源/SRC-EGES/阅读笔记.md)。

比较推荐效果时可锁定请求时点、种子物品和可检索集合，分别评估后续点击或购买命中、长尾覆盖及无邻居回退。用交互图训练时，先按时间截断再构图，不能让待评估行为提前贡献转移。物品是否有显式标签、同一会话是否有顺序或终点、跨会话的路径是否提供可靠信号，是选择正例来源的直接依据。
