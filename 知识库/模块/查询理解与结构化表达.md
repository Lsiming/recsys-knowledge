# 查询理解与结构化表达

同一句查询可能同时表达对象、用途和限制。搜索后端要把它们转成可消费的信号；如果多个独立组件给出不一致的实体或意图，下游可能沿错误方向检索。这里的输入是查询及实际可用的上下文，输出是结构字段、任务结果或意图描述。输出怎样定义，要由业务和检索接口确定。

[LinkedIn 固定 v2 精读](../../来源/SRC-LINKEDIN-SQU/阅读笔记.md)将路由、标签、改写、分面建议和信任处理接入小模型的模式约束生成；Schema指输出必须遵循的字段与结构约定。[QP-OneModel 固定 v1 精读](../../来源/SRC-QP-ONEMODEL/阅读笔记.md)依序生成四项基础信号及自然语言意图描述，由搜索后端按类型消费。

## 路由、字段和评估

<a id="q-schema"></a>**多任务输出怎样保持结构和语义一致？** [结构到下游执行](../问题/搜索查询怎样变成下游可执行的结构.md)说明 LinkedIn 的路由、约束标签、可选改写、分面和信任处理。先明确哪个字段能硬过滤、哪个用于召排特征、歧义时何时走回退，再在同一接口验证各字段是否可同时执行。QP-OneModel 的前序字段可作为同次生成中后续字段的上下文。

<a id="q-domain"></a>**领域语言和业务定义怎样进入模型，并被下游正确使用？** QP-OneModel 以领域预训练、业务规则、近期查询及候选内容增强对社交语境的理解，按任务比较旧级联标签、近期人工对齐和可验证奖励。结构结果用于匹配，意图描述用于改写，两个线上实验分别衡量各自增量。[领域和执行对照](../问题/搜索查询怎样变成下游可执行的结构.md#同一次生成也可以提供软性的意图线索)

<a id="q-teacher-judge"></a>**教师标注与代理评委怎样被独立验证？** Query Illuminator 分用版本化提示生成监督与评估。人员搜索黄金集用于核对分面抽取、查询洁净度和 JSON 稳定性，另有人机一致性抽样。人员 GR@10 来自离线代理评委，职位请求失败来自线上随机实验。[证据与口径](../../来源/SRC-LINKEDIN-SQU/阅读笔记.md#用产品规则定义教师目标与评估准则)

## 与已有模块怎样衔接

[P5统一任务接口](../问题/如何用语言接口统一个性化推荐任务.md)可以帮助理解“多任务都写成序列预测”，[多任务共享](多任务学习与多目标决策.md)可帮助分析冲突与负迁移，但它们没有覆盖搜索字段的相互约束、SNS领域定义和意图描述的后端消费。理解产物如何转为检索请求见[查询改写与规划](查询改写与检索规划.md)，结果是否满足需求见[搜索相关性](搜索相关性判断与验证.md)。

比较时先分开字段正确性、跨字段一致性、意图覆盖与下游效果，再看人评、业务收益和资源消耗；不能把格式遵循率当作意图理解正确率。候选入口为[P48](../阅读/候选论文.md#p48)与[P50](../阅读/候选论文.md#p50)，阅读范围和固定版本见[搜索总图](../总览/搜索系统总图.md#版本与阅读边界)。
