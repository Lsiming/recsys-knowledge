# 用户兴趣与序列建模

用户兴趣不是一个固定标签。短期任务、长期偏好和重复消费共同影响下一次行为。序列模块把带时间顺序的行为转成当前决策可用的状态，这个状态既能服务召回，也能参与候选精排或生成下一物品。

一个关键分界是“状态是否依赖当前候选”。先把历史编码成固定状态有利于缓存和检索；给定候选再从历史中选相关行为，交互更直接，但在线成本随候选数增长。长历史还要求区分真正有用的信息与重复噪声。

## 从经典论文开始

经典基础选 [DIN](../阅读/候选论文.md#p10)、[DIEN](../阅读/候选论文.md#p11) 与 [SASRec](../阅读/候选论文.md#p12)。先看 DIN → DIEN 的候选条件兴趣路线，再看 SASRec 的序列预测路线；之后接 [SIM](../阅读/候选论文.md#p13) 与 [HSTU](../阅读/候选论文.md#p27) 的长历史和规模化问题。完整的起点选择见 [经典阅读路线](../阅读/经典论文路线.md)。

先用[自注意力上下文问题](../问题/序列怎样用自注意力建立上下文.md)理解Q/K/V、多头、位置与可见范围；[Transformer精读](../../来源/SRC-TRANSFORMER/阅读笔记.md)说明完整编码器—解码器如何组成，以及它与推荐历史打分器的区别。

已精读的 [SASRec](../../来源/SRC-SASREC/阅读笔记.md) 与 [下一物品问题](../问题/从历史顺序预测下一物品.md)解释因果遮罩、共享物品表、采样目标及窗口成本；其注意力由历史产生，候选只进入末端内积。

[MIND的行为路由](../问题/单向量如何保留多个兴趣并支持检索.md)在个人历史中软聚出多个兴趣，形成可独立检索的向量；它未显式编码位置或时间，与SASRec的顺序状态不同。训练目标选择兴趣，在线仍保留多个兴趣，多路计算与重复候选需一并考虑。

[DIEN](../../来源/SRC-DIEN/阅读笔记.md)把下一行为作为辅助监督，并用候选注意力控制第二层GRU更新；[候选相关兴趣演化](../问题/候选相关兴趣如何随历史演化.md)比较它与SASRec、MIND的监督和复用边界。其最终状态随候选改变，不能视为所有候选共享的单个向量。

[SIM](../../来源/SRC-SIM/阅读笔记.md)先按候选从长历史检索相关子序列，再做时间感知的精细注意力；[长历史检索问题](../问题/长历史怎样在候选条件下压缩计算.md)比较类目硬检索与学习式软检索。原始历史覆盖54000条不等于每个候选的精细网络都处理54000条。

[HSTU/GR精读](../../来源/SRC-HSTU-PAPER/阅读笔记.md)把物品和行为交错，在物品位置因果预测响应，并将其他类别特征合入时间序列；[序列统一候选条件预测](../问题/序列怎样统一候选条件预测.md)比较它与SASRec、DIEN的接口。HSTU是编码器，GR是任务和训练表述；公开多轮全库实验与工业单遍流式实验需要分别理解。

HSTU、Transformer 是架构线索；是否生成语义 ID、是否采用候选打分，需要再看输出与训练配置。序列表征与候选发现的接口见 [召回](召回与检索.md)，候选条件计算见 [精排](精排、交互与概率校准.md)，硬件与缓存成本见 [服务效率](在线服务、更新与计算效率.md)。
