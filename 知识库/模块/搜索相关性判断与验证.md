# 搜索相关性判断与验证

搜索结果需要回答“它是否满足这次查询”。这与“用户有多大概率点击或购买”相关，但不是相同标签：一个热门且高点击的结果仍可能违背查询限制。这里的输入是查询、候选及可用证据，输出是相关性类别、分数或验证决定；如何把它用于过滤、排序或其他环节，需要按实际系统区分。

[TaoSR1 v4摘要](https://arxiv.org/abs/2508.12365v4)把查询—商品相关性预测作为核心任务，针对CoT错误累积、判别幻觉和部署可行性，使用CoT SFT、pass@N与DPO、难度动态采样与GRPO。[LEAPS v2摘要](https://arxiv.org/abs/2601.05513v2)在扩展后的下游引入Relevance Verifier，结合OCR文本、评论等多源信号进行CoT验证。前者摘要着重相关性推理模型，后者着重扩展后去噪；不能从共同使用CoT推定二者职责完全相同。

## 三个待研究问题

<a id="q-reasoning"></a>**相关性推理怎样避免解释合理、判别却错误？** TaoSR1摘要将错误累积与判别幻觉列为挑战，并分阶段改善推理生成和判断。后续需读清相关性标签定义、难度采样、偏好对构造、推理过程与最终类别的关系；查询中的用途、属性与业务规则怎样被处理，不能由CoT这一形式自动推出。原清单中“自适应引导RL”和用户历史融合尚未用该版本正文确认。

<a id="q-evidence"></a>**扩展后的候选怎样依据多源证据验证原始需求？** LEAPS摘要将扩展召满和验证去噪分开，以OCR、评论等补充判断信息。待研究的是验证器面对原查询还是扩展查询、证据之间冲突或缺失怎么办，以及缺少关键属性应判不满足还是不确定。扩大候选后的有效结果增量、错误过滤和多源证据增量，应在精读时分别寻找证据。

<a id="q-budget"></a>**推理式判断怎样在在线预算内被可靠使用？** TaoSR1摘要提到CoT后处理与基于累积概率的分区方法支持部署，但尚不能据摘要还原具体算法。要核实哪些查询/候选需推理、阈值怎样确定、难例与长尾错误怎样变化、模型调用和证据获取总成本多大，以及报告的人类并排评价覆盖什么场景。不能把人评提升直接写成点击或交易提升。

## 与精排和评估怎样分工

[精排与概率校准](精排、交互与概率校准.md)保留行为概率、特征交互与效用建模；本模块新增查询满足关系和证据验证这一对象。共享[训练与对齐](训练目标与偏好对齐.md)中的监督分析，但DPO/GRPO学到的奖励、人工相关性和线上行为必须分别定义。查询中的结构信息来自[查询理解](查询理解与结构化表达.md)，验证器接在扩展之后时参看[改写与规划](查询改写与检索规划.md)。

后续比较拟固定相关性标注标准、查询难度和约束类型、候选来源、证据可用时间，分别审查误判、难例召回、验证过滤损失、延迟与线上收益；目前没有跨论文统一实验。阅读入口为[P41 TaoSR1](../阅读/候选论文.md#p41)、[P51 LEAPS](../阅读/候选论文.md#p51)，正式题名、版本与阅读范围见[搜索总图](../总览/搜索系统总图.md#版本与阅读边界)。
