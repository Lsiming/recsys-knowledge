# 搜索联想与查询补全

联想发生在用户尚未完整表达需求时。输入是前缀及当时可用的上下文，输出是一组供用户选择的查询；它既帮助表达，也可能改变后续搜索方向。商品推荐输出物品，查询改写通常处理已提交需求，二者都不能替代前缀到建议查询这一接口。

[OneSug](../../来源/SRC-ONESUG/阅读笔记.md)用量化检索获得参考查询，再用日志行为等级学习偏好。[LocalSUG](../../来源/SRC-LOCALSUG/阅读笔记.md)更新城市共现参考，并从模型的训练束分配相对奖励。两条方案按输入参考、候选比较和线上衡量统一归入[短前缀查询建议](../问题/短前缀怎样生成相关且有排序能力的查询建议.md)。

## 前缀生成与两个延伸问题

<a id="q-prefix"></a>**信息不足的前缀怎样生成相关且有区分度的建议？** [OneSug的已读方案](../问题/短前缀怎样生成相关且有排序能力的查询建议.md)先以业务配对对齐BGE，混合共现查询表示，再用RQ-VAE桶取得参考；生成器输出文本，行为等级构成成对或多负例偏好。共现与反馈仍受旧曝光影响，完全无共现前缀的回退、奖励差稳定及公式梯度需进一步核实。既有[用户兴趣](用户兴趣与序列建模.md)提供历史表示背景。

<a id="q-city"></a>**同一前缀怎样适应城市差异和本地供给变化？** LocalSUG 按过去七天的点击共现每天更新城市与全局列表。构造提示先从城市列表取参考，再用全局候选补位。城市缓存依赖日志成熟度，商家突发关闭或没有共现的店铺仍需额外供给信号。[城市参考与 OneSug 对比](../问题/短前缀怎样生成相关且有排序能力的查询建议.md#用城市日志更新提示并在解码候选上训练)

<a id="q-decoding"></a>**偏好训练怎样对齐实际生成列表和严格延迟？** LocalSUG 训练时用更宽的束搜索取得同组候选，线上用分数阈值、饱和条件与词表裁剪加速解码。日志目标仍受历史曝光影响，解码吞吐与线上请求均值或尾延迟有不同的计时范围。[训练与部署证据](../../来源/SRC-LOCALSUG/阅读笔记.md#训练束比展示列表更宽)

## 怎样评价建议查询

前缀匹配、建议本身的可读/相关、用户选择、选择后的检索有效性与业务转化属于不同节点。本库拟按前缀长度、长尾程度、城市与供给变化分层，并同时看覆盖、重复、无结果和整条链路时延；OneSug报告足额16条、查询/整页语义优质率及线上CTR、订单、收入；这些轴不全是两篇都已测量。它的full recall rate实际是足额返回率，不能当相关查询全集召回；具体证据与缺项见[问题页](../问题/短前缀怎样生成相关且有排序能力的查询建议.md#先问建议是否可用再看被选择与业务转化)。点击最多的建议也可能受展示位置影响，需与[训练和曝光边界](训练目标与偏好对齐.md)一起审查。

查询被选择后再进入[改写与规划](查询改写与检索规划.md)；多路径生成与成本继续复用[解码模块](生成机制与约束解码.md)和[在线服务](在线服务、更新与计算效率.md)。阅读入口为[P42 OneSug](../阅读/候选论文.md#p42)、[P43 LocalSUG](../阅读/候选论文.md#p43)，固定版本及阅读范围见[搜索总图](../总览/搜索系统总图.md#版本与阅读边界)。
