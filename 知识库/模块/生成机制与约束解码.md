# 生成机制与约束解码

“生成”需要先说明生成什么：物品 ID 的 Token、已有候选的排列、用户偏好向量，还是可展示内容。不同输出对应不同的合法性条件。推荐已有商品时，输出文本听起来合理并不足够，最终必须映射到当前可推荐的物品。

自回归方法逐步选择Token，局部高概率路径未必对应最优整张列表。连续扩散通过去噪得到目标表示或交互信号，不直接采用Token前缀搜索；离散掩码扩散也可以结合束搜索，但要分析填充位置、同轮组合和目录合法性。三种接口不能仅凭“多步生成”共用同一成本或概率解释。

## 从经典论文开始

先以 [Seq2Slate精读](../../来源/SRC-SEQ2SLATE/阅读笔记.md) 建立列表逐步生成的基础，再以 [TIGER精读](../../来源/SRC-TIGER/阅读笔记.md)进入生成检索，最后读 [Decoding Matters精读](../../来源/SRC-DECODING/阅读笔记.md)。这里标的是基础代表与新路线起点，不把较新的语义 ID 解码工作统称为成熟经典。完整的起点选择见 [经典阅读路线](../阅读/经典论文路线.md)。

[Seq2Slate](../问题/列表顺序与前缀依赖怎样建模.md)的输出是候选索引排列，mask避免索引重复；TIGER则生成语义码并映射物品。两者虽都逐步生成，合法性空间和召回职责不同。Seq2Slate贪心是逐步局部选择，beam search和离策略校正在原文仍属未来工作。

[LC-Rec的合法索引搜索](../问题/用语义短码直接检索物品.md#末层平衡分配与追加身份码有不同的保证条件)明确将可能导致非法索引的Token概率置零；beam20仍是近似搜索，静态索引合法不等于动态库存和业务资格均满足。

[D³解码校正](../问题/物品生成怎样校正长度偏差与同质化.md)取消对近乎确定Token仍计长度的归一化，并将SASRec物品概率汇聚为前缀条件概率，逐步融合搜索得分；与DPP生成后集合重排的作用位置和保证不同。取消归一化不会减少Token生成步数，主表数字疑点与真实服务成本见精读。

[多物品推测解码](../问题/多物品生成怎样减少串行模型调用.md)比较严格beam复现与宽松采样近似：草稿要覆盖全部K条目标路径，树形注意力复用共享前缀。接受步数不等于实际耗时加速，宽松模式不保证原top-K排名，原文推导和伪代码疑点已在精读保留。

[DiffRec交互向量去噪](../问题/交互向量怎样通过去噪生成推荐.md)从用户历史出发，预测连续全目录分数；L-DiffRec在压缩潜向量上去噪，再解码全部物品。[DreamRec](../../来源/SRC-DREAMREC/阅读笔记.md)则从纯噪声生成条件oracle表示，再做向量近邻检索。三者都要把多步去噪或解码成本计入端到端延迟，不能把扩散步骤当成beam搜索步骤，也不能把连续目标的近邻映射当成语义码的合法Token约束。

[MDGR的离散码补全](../问题/交互向量怎样通过去噪生成推荐.md#离散目标码按置信度补全)使用并行码本，双向解码器从全掩码目标SID出发，先逐位置预热，再按置信度并行填充。其束搜索对本轮$m$个位置各取Top-$B$、展开$B^m$组合，并非固定左到右前缀；已填Token没有重掩码修正，组内概率乘积也不等于显式组内联合建模。完整码仍需映射、去重与资格过滤，论文未充分给出无效码或碰撞处理。默认8码、预热4轮、每轮2位置共6轮，少轮次可能伴随更大组合成本。[原文§4.4–4.5，第5–6页](https://arxiv.org/pdf/2601.19501v2#page=6)。

[GRID组件比较](../问题/用语义短码直接检索物品.md#简单量化与复杂生成之间怎样分配预算)说明简单量化、码长、碰撞消歧与合法码搜索应分开评价；平均命中接近不能替代每件物品唯一寻址或合法性保证。实验收益依赖当前数据、样本增强及默认配置，未验证量化线上加速。

[生成对象与评估目标](../问题/生成式推荐怎样选择输出对象与评估目标.md)依据Gen-RecSys综述区分训练样本生成、物品选择、语言交互与内容合成；同一自回归/扩散模型可接不同接口，不能只按骨干命名决定候选空间或评估方式。

## 三条模型路线需要落到同一输入输出接口

[DMT综述§4](../../来源/SRC-GENREC-DMT/阅读笔记.md#模型侧三个入口多个独立设计决定)并列预训练LLM适配、推荐原生大型模型和扩散；它们强调预训练来源、模型扩展与生成机制的不同侧面，可以交叉组合。LLM既能生成ID，也能输出连续表示再检索；HSTU式候选条件建模不能等同OneRec式会话码生成；扩散可以合成训练数据，也可以生成目标表示。

比较时补齐“输入→训练监督→生成对象→目录映射→最终结果”。扩散内部位置可并行，不代表多轮去噪加搜索的整体成本必低于短码自回归；连续目标也需要目录检索或解码。[TokenRec](../../来源/SRC-TOKENREC/阅读笔记.md)把连续查询投影和目录近邻检索作为两步接口，避免了逐Token生成，但仍要计入ANN、过滤、补位和向量库更新。已有[DiffRec](../问题/交互向量怎样通过去噪生成推荐.md)是全目录分数，[DreamRec](../../来源/SRC-DREAMREC/阅读笔记.md)是连续oracle物品表示；三者输出空间不同，框架比较不能替代原论文实验。

TokenRec也说明接口名称不能代替损失定义：其式(20)虽被称为pairwise loss，实际是对正例最小化\(1-\cos(z,q)\)，对负例最小化\(\max(0,\cos(z,q)-\gamma)\)，没有直接优化正负分数差。它与BPR及自回归Token交叉熵具有不同监督形式；“生成式”这个名称不能据此推导训练目标相同。[训练机制精读](../../来源/SRC-TOKENREC/阅读笔记.md#llm输出连续查询目录检索负责返回真实物品)、[原文§II-E、式(20)，第7页](https://arxiv.org/pdf/2406.10450v3#page=7)。

## 内部潜状态与最终目录输出分别定义

[LatentR³](../问题/推荐潜推理怎样从答案反馈中学习.md)从当前LLM隐藏序列生成连续潜Token，再把它作为输入生成物品标题；默认一个潜Token仍需要隐藏状态提取和后续生成。这个向量是内部计算状态，没有固定物品身份，区别于LLaRA的外部协同输入、TokenRec的检索查询和TIGER的离散地址。最终标题仍要约束到目录，潜推理本身不提供库存可用或列表无重复保证。潜状态长度、答案解码宽度与目录映射应分开控制，PPL奖励也不能替代映射后完整列表的排序评估。[机制与成本精读](../../来源/SRC-LATENTR3/阅读笔记.md)。

[PreferDiff的连续扩散偏好](../问题/交互向量怎样通过去噪生成推荐.md#连续目标扩散怎样引入负样本)保留DreamRec的Gaussian初态、条件引导与目录内积映射，只在训练引入正例和负质心恢复的相对误差。它没有增加合法Token前缀树，也没有消除物品范数、已交互过滤或库存资格问题。论文20步DDIM与固定代码默认21轮需分别描述；减少去噪轮数、每轮两路引导和最终目录搜索都应纳入成本。[机制、代码及计时核对](../../来源/SRC-PREFERDIFF/阅读笔记.md)。


## 显式理由、物品地址和线上前缀不是同一层输出

[OneRec-Think](../../来源/SRC-ONEREC-THINK/阅读笔记.md)在自回归输出中先生成文字理由，再生成目录物品码。理由表达上下文分析，物品码负责寻址；训练中的码匹配奖励不自动提供无冲突、库存可用或列表去重保证。工业Think-Ahead进一步将离线理由压成候选前缀集合，线上由实时OneRec在其约束下完成末级码，区别于单模型每次请求完整生成长CoT。[v2 §3–4.4，第3–5页](https://arxiv.org/pdf/2510.11639v2#page=5)。

推理文本、内部连续潜Token、离散物品码与缓存前缀分别承担不同职责。评价需要控制理由长度、候选搜索宽度、前缀覆盖和合法目录映射；更长理由不必然改进推荐，候选内容与理由一致也不是忠实性证明。连续与文字推理的训练反馈比较见[推理问题](../问题/推荐潜推理怎样从答案反馈中学习.md#显式文本推理把答案反馈接到另一种中间对象)。

## 跨域条件与合法目标目录分别约束生成

[UniGCRec](../../来源/SRC-UNIGCREC/阅读笔记.md#生成目标逐域适配与目录合法性是后续三层)以用户CSC-ID携带跨域信息，后接仅目标域历史；目标域LoRA与该域前缀树进一步限定输出。前缀树由目标物品池的码构建，逐步只保留可延伸到目录物品的分支，实验束宽20；式(13)的单步argmax不是完整beam算法。用户码决定条件信息，物品树决定可输出地址，两者分工不同。

合法码组合不能替代碰撞叶消歧、历史过滤、列表去重/补位与实时库存资格；正式正文未完整披露这些规则。用户码、物品码本、LoRA和目标树还要保持版本相容，新域或新物品直接可用也未得到验证。[§3.3–3.4，出版892页，DOI全文](https://doi.org/10.1145/3770855.3818132)。
