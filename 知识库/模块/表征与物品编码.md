# 表征与物品编码

推荐中的表示承担两项不同职责：表达物品之间的关系，以及让系统准确指向一个可返回的物品。连续向量适合计算相似度；离散 ID 便于索引或生成，但 ID 的语义、唯一性和更新方式都需要另行设计。

协同表示从用户—物品交互学习“哪些物品被相似的人消费”；内容表示从文本、图像等描述学习相似性。两者提供的信息并不相同。冷启动时内容可在交互不足前提供线索，是否转化为推荐收益还取决于对齐、分布和候选资格。

[Item ID 清单](../../来源/SRC-ITEMID-SURVEY/阅读笔记.md)把构建标识与对齐分开。[GRID README](../../来源/SRC-GRID/阅读笔记.md)明确展示“文本向量 → 语义 ID → 推荐生成”，并说明额外层级可用于区分重复语义 ID。这表明量化质量与物品唯一可寻址性需要分别检查，不能只看向量重建误差。

[TIGER](../../来源/SRC-TIGER/阅读笔记.md#共享语义与唯一寻址是两件事)已经给出论文依据：三级内容残差码后加一位消歧码，语义共享与唯一寻址分别处理；推荐训练在ID冻结后进行，并非内容与协同端到端联合量化。

[交互图协同表示](../问题/利用交互图传播协同表示.md)比较BPR-MF与LightGCN：同样以正负分差监督，后者在预测结构中显式归一化聚合邻居、组合各层表示。它只有初始ID参数，但传播有额外边遍历成本；不能将纯ID实验中去掉非线性的收益推广到全部富属性图。

一个离散码可写为 z(i)=(c₁,…,cₗ)。共享前缀只说明编码设计让物品共享了部分路径，并不自动保证推荐偏好相似。编码如何用于找候选见 [召回](召回与检索.md)，如何约束合法路径见 [生成与解码](生成机制与约束解码.md)，如何注入行为监督见 [训练与对齐](训练目标与偏好对齐.md)。

[P5的ID子词与TIGER语义码比较](../问题/如何用语言接口统一个性化推荐任务.md#id子词共享与语义码共享解决不同问题)区分两类共享：P5整词Embedding帮助识别输入字段，ID数字片段不是内容量化码；TIGER另训练RQ-VAE建立共享语义层级与消歧映射。

[LC-Rec与TIGER的消歧比较](../问题/用语义短码直接检索物品.md#末层平衡分配与追加身份码有不同的保证条件)区分末层平衡传输和额外身份码：平衡软质量不自动证明硬码唯一，固定末码容量仍约束同前缀可寻址物品数。

[GRID组件比较](../问题/用语义短码直接检索物品.md#简单量化与复杂生成之间怎样分配预算)说明简单量化、码长、碰撞消歧与合法码搜索应分开评价；平均命中接近不能替代每件物品唯一寻址或合法性保证。实验收益依赖当前数据、样本增强及默认配置，未验证量化线上加速。

## 编码输入与生成输出分别选择

[DMT综述§4.1、表2–4](../../来源/SRC-GENREC-DMT/阅读笔记.md#预训练llm怎样接上行为)从文本、连续协同Token、数字ID和专属ID Token解释LLM适配，并将Token化进一步分为独立ID、文本、码本、协同码本及自适应路线。输入使用离散Token，并不要求输出也逐Token生成ID。[TokenRec](../../来源/SRC-TOKENREC/阅读笔记.md)给出一个已核实的“离散协同输入 → LLM连续查询 → 全目录向量检索”接口：MQ Tokenizer先对GNN协同向量做元素掩码、K路最近邻量化和K到1重建，LLM只负责产生查询表示，实体合法性和目录更新仍由向量库与后处理承担。

TokenRec的K路码本容量降低了词表扩张，但组合容量不能代替碰撞率、码使用率和唯一寻址验收。“User ID Only”只是不在提示中逐项列历史，用户码仍含历史交互的协同信息；其unseen-user实验允许更新上游GNN和向量库，更新可见交互和时间边界未充分披露，因此不能直接等同于无交互冷物品零样本或完整排除泄漏。与TIGER/LC-Rec的内容语义码相比，TokenRec更直接保留协同关系，却需要稳定的交互图表示和目录向量检索。[TokenRec精读的泛化协议](../../来源/SRC-TOKENREC/阅读笔记.md#unseen-user实验并不等于真实冷启动物品)定位[原文§III-C，第9–11页](https://arxiv.org/pdf/2406.10450v3#page=9)；效果和延迟数字仅适用于该论文的切分、T5-small、A800和候选协议。

内容是否带协同信息、码是否唯一、生成器如何寻址、旧码如何更新，是四个分别需要证据的问题。[LETTER精读](../../来源/SRC-LETTER/阅读笔记.md)补齐“协同信息在哪个阶段注入”：它在训练Tokenizer时对齐内容量化表示与CF向量，使行为信号能改变码分配，并以码向量多样性正则缓解集中。官方实现为交叉熵，论文印式缺少log，需分开核对；码使用率改善也不等于完整码无碰撞或展示公平。与TIGER/LC-Rec及TokenRec的比较见[语义码问题](../问题/用语义短码直接检索物品.md#letter把协同监督提前到码分配阶段)。连续行为表示与语言适配由下文LLaRA补充。

[LLaRA的连续行为输入](../问题/如何用语言接口统一个性化推荐任务.md#llara用连续行为位置补充文本提示)补充另一种接口：冻结推荐器的64维物品向量经MLP投影为一个4096维输入位置，与标题文本位置拼接，历史和候选都这样表示。其输出是候选标题，输入的行为Token未量化为物品地址；应与LETTER的离散Tokenizer、LC-Rec的码—文本对齐及TokenRec的连续查询检索分别理解。

[OneMall电商编码](../问题/用语义短码直接检索物品.md#onemall用业务关系调优表示末层fsq缓解冲突)进一步区分“统一量化框架”与“相同编码信号”：商品卡使用商品语义、短视频合并商品与观看语义、直播使用动态双塔及在售商品SID。末层FSQ能缓解冲突，但表中仍有11% Conflict，完整码到多物品的线上映射尚未披露；规则格点不等于无碰撞或库存有效。

[MDGR的并行码本](../../来源/SRC-MDGR/阅读笔记.md#并行码本给各位置平等的生成角色)将内容向量分别投影到多个子空间，各自最近邻量化，形成8位置、每本300个256维码字的SID。它减少残差量化中后层依赖前层残差的结构约束，便于按置信度改变填码顺序；这不保证码位置统计独立、对应人工属性或组合唯一。作者称OPQ，但显式公式未充分披露正交旋转和码本训练细节，不能仅凭名称补造实现。与TIGER、LETTER的残差码相比，编码结构和生成顺序都变了，目录碰撞、无效组合与动态更新仍需独立验收。[§4.2、§5.1.3，第4/8页](https://arxiv.org/pdf/2601.19501v2#page=4)；[离散扩散接口](../问题/交互向量怎样通过去噪生成推荐.md#离散目标码按置信度补全)。

[FedCGR的固定公共SID与私有CF接口](../问题/联邦跨域推荐怎样共享语义又保留私有行为.md#先稳定地址再适配本地协同)给出另一种协同注入位置：Tokenizer固定以保持跨客户端码义，SID Token向量仍训练；独立CF坐标由各域本地适配器映射，再以物品频次置信度和域标量门加到历史表示。它不跨域平均未对齐CF向量，也不像LETTER让协同监督直接改变Tokenizer。目标域前缀树允许碰撞叶存多物品、用验证集流行度破同分，合法路径不等于唯一地址或无反馈泄漏。

[OneSug的参考查询桶](../问题/短前缀怎样生成相关且有排序能力的查询建议.md#量化码用于寻找参考文本才是输出)说明RQ-VAE还可以用于生成器外部的上下文检索：业务配对对齐BGE，混合前缀与共现查询表示，再按完整/部分相同码找参考。最终输出仍是查询文本。其4层×512码字不等于目录大小或唯一寻址保证，不宜与TIGER、LETTER的目标物品码接口合写；共享量化工具并不要求共享生成输出。[OneSug §3.2–3.3，第4–5页](https://arxiv.org/pdf/2506.06913v1#page=4)。

## 物品码进入语言以后还要学习组合与行为关系

[OneReason](../../来源/SRC-ONEREASON/阅读笔记.md#三个物品子码只是地址基础语言对齐还要训练)先以多模态内容理解训练物品向量，再用三级、每级8192码的RQ-KMeans形成“域begin+三个子码”。其后四粒度预训练分别处理子码组合、容量适配的物品描述、多物品关系和用户行为上下文。量化解决紧凑地址，后续语料才训练语言骨干如何使用它们，不能把8192³组合容量当作唯一性或天然语言对齐保证。[v1 §4，第11–19页](https://arxiv.org/pdf/2606.06260v1#page=11)。

这与LETTER把协同约束注入Tokenizer、FedCGR固定公共Tokenizer后在输入侧适配私有CF的位置不同。OneReason将协同关系配语言说明以训练骨干，关系文本不因可读就成为因果证据；三子码无法承载的细节还需在监督粗化时取舍。编码、语言对齐、目标奖励和目录更新应分别检验，进一步见[训练模块](训练目标与偏好对齐.md#多粒度预训练分层监督和专家整合解决不同缺口)。

## 用户码作为条件时，分开检查对齐与共享范围

[UniGCRec](../../来源/SRC-UNIGCREC/阅读笔记.md#对称的是表示职责用户物品并不共用同一码本)先对齐融合画像/协同的用户表示与文本/协同的物品表示，再分别用用户RQ-VAE和物品RQ-VAE量化；两套码本各自跨域共享。默认同为3级×256码字不意味着同数字同义，生成器也区分用户/物品及层级词表。用户码是前缀条件，目标物品码才是目录地址；目标域历史仍作为输入。

这与TokenRec的离散协同输入、连续查询输出，以及LETTER在物品Tokenizer学习中引入CF的位置不同。批内对齐促使量化前表示相容，t-SNE混合只提供定性几何证据，不能证明码相同、唯一寻址或跨域无负迁移。UniGCRec正式式(9)未显式写重建项，几何/多样性正则和RQ模块更新范围未完整展开，公开摘录也没有训练损失；使用一般RQ-VAE常识不能补造本篇实现。[§3.2–3.3、图5，DOI全文](https://doi.org/10.1145/3770855.3818132)。
