# 论文精读怎样写到读者能沿计算走下来

本页承接[论文标准流程第4步](工作流.md#4-保存一篇可独立学习的技术精读)，是阅读笔记的写作与语义验收操作定义；[模板](../文档/模板/论文笔记模板.md)只提供可删改的文章骨架。第一优先级是方便用户学习、理解与反复查阅；维护效率、形式整齐和流程收据服从这一目标。初读按理解依赖组织，复习用少量精确章节导航，不强求一屏塞完。目标是主动补齐理解主线的必要台阶，而非等用户连续追问后才拼出方法。不能保证没有后续疑问，也不以字数、公式数量或关键词命中代替理解。

## 起草前找出真正需要讲透的内容

读固定版本的正文和支撑关键主张的附录。先用简短工作提纲确定：任务与输入输出、核心主张、改变的计算步骤、相应证据和边界。核对库内先修页及该论文/相邻论文的实际学习思考；工作提纲留在临时上下文，多步改造的检查结果进交接，不把Agent清单贴进学习正文。

按**内容的角色**选择展开深度，不按论文年龄或名气划分整篇：

- **奠基或首次系统提出的关键思想**：从问题的具体困难建立直觉，解释原语、状态与信息流，走完关键公式或算法，并用例子说明它为何解决该困难。历史“首次”需有可靠依据；不确定就写本篇关键贡献，不能由作者自称或论文经典地位推出首创。
- **沿用的公共模块**：先解释它在本篇接收什么、做什么、输出给谁，再链接公共详解。非本篇关键的已知细节可以收敛，但不能跳过连接新机制的接口。
- **在经典方案上改进的部分**：先让读者看懂旧方案如何处理同一输入，指出它在哪一步遇到限制，再说明新方案具体改变、引入的假设与代价。对“为什么这样设计”区分作者明说的动机、由结构推出的解释和经过消融支持的效果，不编造作者思考史。

同一篇可以兼有三类。BERT沿用Transformer编码器，双向掩码预训练是本篇需要讲深的核心；不能因此把Transformer或所有遮罩思想都归为BERT首创。

## 用同一实例接通方法

算法和模型论文优先选一个足够小、但能暴露关键机制的实例，从原始数据一直追踪到使用结果。教学Token、概率和维度明确是构造值，不冒充真实分词、模型输出或实验。若一条实例不能覆盖不同任务，保留主实例，分支另举最小例子，不强行混为一种监督。

按计算依赖写成连贯正文：输入如何构造、标签从哪里来、关键中间量是什么、在哪输出、怎样计损失、哪些参数收到信号、训练后如何使用。理论论文换成命题、假设、证明步骤和反例；系统/非神经算法换成状态、操作、约束与复杂度，不硬套LM Head。

[GPT实际疑问](../来源/SRC-GPT1/学习思考.md)暴露的下列环节是模型论文的优先审查点。按相关性展开；不要求每篇逐题填表，更不能把自问冒充用户实际追问：

| 容易跳步的连接 | 写作时要让读者实际能判断什么 |
|---|---|
| 样本到输入与标签 | 同一行预测谁，标签是否错位；样本/负例怎样得到，什么信息预测时可用 |
| Token、Mask到信息可见性 | 输入符号替换、Attention连接、Padding、Loss位置各管什么，是否泄漏目标 |
| 骨干到Hidden State | 每个位置是否有状态，各轴/维度表示什么；上下文如何进入，层内并行与逐步生成的区别 |
| 状态到输出头与读出 | 选哪些位置，投影到词表/类别/位置还是候选；CLS、Last、Mean的监督和可见范围 |
| 输出到Loss与梯度 | 真值如何选概率，在哪些位置归约；信号经头到共享骨干，不把未直接计loss误作不训练 |
| 预训练到微调及推理 | 保留/新增/丢弃什么，用哪些标签、更新哪些参数；输入与输出是否换义 |
| 设计到实验结论 | 机制解释有没有对应控制证据，改了哪些因素，结果能支持到哪里 |

关键公式先说“用来算什么”，再定义符号、来源、形状和条件，随后说明从前一步怎样得到。对承重步骤给必要中间式或小数值计算；区分恒等式、条件结论、近似和直觉。公式旁边一句“衡量差异”不算解释。无需逐式抄录不影响理解的公式，也不捏造论文没给的实现；只有实现会改变答案且原文不足时，定向查固定commit官方代码，注明静态阅读与真实运行之别。

## 轻解释要让当前段能继续读

公共概念详解在知识库维护唯一主要正文，笔记保留其**本篇实例化**：它是什么、为什么在这里需要、当前变量/位置怎样使用、结果接到哪里，然后链接准确章节。读者暂时不跳转，也应能跟上下一步；需要通用证明、其他变体或更基础原理时再跳转。轻量不是固定字数，也不是括号补一个中文译名。

例如BERT处写：“隐藏状态是每位置随上下文更新的向量；此处取被选中的同位置状态，送词表头恢复该位置原Token，而非像GPT用这一行预测下一Token。”再链通用的状态到词表和交叉熵推导。不要只写“接MLM Head，见链接”，也不要复制整页Softmax Jacobian。若轻解释与公共页出现冲突，先核对证据并修正，不能两处各维护一套定义。

## 图必须帮助读懂一个具体步骤

检查原文结构图、训练/推理图、关键消融图哪些承担理解作用；在讲到相应机制时嵌入可直接渲染的图片，并解释读图顺序、箭头/轴、一个具体读数及图未表达的边界。图不能替代公式与文字，也不为“有图”贴满论文全部图表。

图片按[单实体图片规范](图片资源规范.md)存放与引用。优先复用已有实体；原创机制示意优先小型SVG并注明依据与简化，原图须逐图核实公开使用条件。许可未明可链接固定原文页并画自己的解释图，不把截图换个格式当原创。笔记和知识页通过各自相对路径引用同一实体，不复制到多个assets目录，不依赖热链或Obsidian专有嵌入语法。正文图即使离线打开知识库也应能显示。

## 写实验是为了检验解释

先提出需要检验的主张，再选对比与消融：数据、指标定义、资源、训练/选择协议、基线和改变量是什么，结果支持哪一环、还有哪些竞争解释。强主张需邻近证据；没有对应消融就说明未隔离证明，不把合理动机写成已证事实。保留负面结果、例外和原稿中有价值的条件，不因改写更顺畅而删掉限制。不能把多个混合指标平均称统一准确率，也不能拿跨论文主表排除训练预算等混杂。

## 成稿前做两轮CR并直接修复

每个实质阶段结束先做当前Agent自查；大任务把发现、修复和真实验证记入任务交接，普通论文不另建流程档案。最后按完整正文再做两轮：

1. **技术与证据CR**：沿实例核对输入、索引/形状、公式、计算、梯度与训练推理边界；对关键主张回查固定原文/代码，检查经典方法对照、消融归因、数字条件、事实与推断。逐图核内容、来源、路径与可读性。发现错误直接修复；原文缺报写具体缺口，不补造。
2. **读者路径CR**：暂时只读笔记，尝试复述“旧方法怎样做、哪里不足；新方法拿到什么、逐步做什么、为何可能有效；一个样本如何训练、训练后如何用；证据能证明到哪”。检查每个承重术语首次出现是否有本篇解释、每次跳转是否可选、相邻两步之间能否衔接。若只能报模块名、背公式、按关键词找到答案，却无法走通实例，回到对应段重写。

CR不能只检查标题齐全、图表数量或篇幅；小算例可用脚本核验，链接检查器不能证明落点回答了问题。当前Agent自查不称独立审查，只有用户实际反馈/测试才能证明其理解是否改善。基于新流程回写的笔记才报告本次覆盖；不追认所有历史笔记已达标。

修复后重查受影响段与整条主线，再执行标准流程的来源plan、直接引用页复核、索引、lint和本地提交。后续实际疑问继续走[学习思考整理](工作流.md#论文疑问与学习思考整理)，但不能将它当作基础讲解缺失的默认补救方案。
