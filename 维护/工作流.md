# 维护工作流

[知识契约](../SCHEMA.md) 定义字段与证据；本页是唯一操作流程。常规论文和问答直接处理，只有跨会话中断、并发、系统改造或实验才登记 [任务队列](../TODO.md)，不为每篇论文重写根上下文。

## 论文知识沉淀标准流程

用户提供 URL、arXiv ID、PDF 或题名，即默认执行 **核实原文 → 翻译 → 精读 → 按问题提炼与比较 → 检索与验证 → 本地提交**。这是后续论文的统一做法，实际范例见 [ESMM 精读](../来源/SRC-ESMM/阅读笔记.md)与[问题页](../知识库/问题/点击后转化率估计.md)，首次执行证据见 [R001](../文档/会话/R001.md)。已有产物增量补齐；模块归属由 Agent 判断，身份唯一且原文可取得时直接推进。用户明确只需其中一步时遵从。

### 1. 定位论文与已有知识

核实题名、作者、年份、arXiv/DOI、实际采用的版本和检索日期。先检索来源题名/标识、问题关键词、方法名及别名，读取最相关的阅读笔记和问题页。同一论文沿用来源 ID，同一问题优先合并；新版保留旧版本，不重建平行来源。题名不能唯一定位时才澄清身份。

### 2. 取得原件与可编辑源码

获取固定版本的原始 PDF；有 arXiv 版本时，按 `arxiv-translator` 的顺序获取 LaTeX 源码、定位主文件和实际参与编译的子文件。**取得源码后先保留未修改副本，再在副本上翻译**；哈希冻结的是证据原件，译后源码持续可编辑。

以正式 PDF 确认出版正文范围。源码中的注释旧稿、模板示例、未发表实验不算论文内容；检查附录是否属于采用版本。优先保存上游原始压缩包；只有解压文件时可打包留存，但来源卡必须注明“下载后未修改文件的本地重新打包”，不能声称是上游压缩包原字节。LaTeX 是排版源码，不等于算法实现代码；有必要查官方实现时另固定 commit 与实际阅读范围。

### 3. 翻译、编译与原文核对

有 LaTeX 时执行 `arxiv-translator` 的确定 ID、下载源码、当前模型翻译与扫描、编译四步。翻译正文、摘要、图表标题、描述性脚注和代码注释；公式、代码本体、引用标签、图片路径和专名按 skill 保留。默认附录保留原文，用户要求全文时再翻附录；图内英文未重绘等范围在阅读笔记文末说明。原文疑似错误保留并加译注，不悄悄改写。

扫描后逐项处理残留，检查所有实际编译子文件；主文件的 `body` 扫描可能漏掉无文档边界的子文件，需补充扫描或人工核对。随后编译；服务不可用时按 skill 的重试上限处理，再用已有本地编译工具，按实际引擎配置中文支持。不把服务失败当作论文错误，也不把进程退出或生成了文件当作 PDF 已验证。

核对关键公式/符号、表格数值与单位、图表/文献引用；渲染最终 PDF 并逐页目视检查中文缺字、裁切、图表可读性、公式、引用和出版年份。修订后重新检查受影响内容与最终 PDF。保留可继续编译的译后源码、图片及必要样式/参考文献；临时目录只在有效产物已保存后清理。已有工具不足时说明具体限制，不为一次翻译擅自安装庞大环境。

正式 Markdown 译文公开前按 [许可规则](../LICENSE) 核实该固定版本允许翻译再分发，写入 `译文/<ID>/中文译文.md`，并在 `译文/目录.json` 登记作者、原文版本、许可核实入口/日期、翻译范围、修改说明与 SHA256。未确认公开授权的全文译文不公开，按当前范围保留本地或私有备份；不把 arXiv 非独占分发许可当作公众翻译许可。

原文 PDF 取得并登记后，以及中文 PDF 完成核查后，按[PDF私有维护流程](../文档/工具/中文PDF发布.md)备份到独立私有附件库。原文保留原字节与来源快照哈希；不同版本、未核实镜像和译文分开登记，保留原作者署名及权利声明。译文仍核查固定版本的许可，但私有存储决定不等于公开翻译授权。上传前核对私有可见性、版本/范围/隐私，上传后用有权账号实际下载核验大小与SHA256；成功后才登记已私有备份。后续同类附件及配套目录更新已获持续授权，公开PDF发布授权已被本规则替代，不自动邀请账号或扩大访问。公开库只更新许可/范围盘点与访问说明，笔记保留公开原文入口并链接PDF访问说明；不提供需登录的逐篇链接作为公开下载。Markdown与PDF分别登记。

无 LaTeX 时明确该 skill 无法完成源码翻译，改用可读取的 PDF，至少保存按原文章节与页码可核对的中文 Markdown；无法生成 PDF 就说明实际格式。译文遇阻仍继续可做的原文精读和归纳，将未完成阶段及原因简记在阅读笔记，不能宣称全流程完成。译文是辅助，关键事实回查原文。

### 4. 保存一篇可独立学习的技术精读

写入 `来源/<ID>/阅读笔记.md`，用连贯文章解释“问题 → 已有方法缺口 → 具体解法 → 为什么这样设计 → 证据与边界”。讲清输入/输出、关键结构、公式符号、训练目标、采样与推理；必要时用最小例子或示意图。阅读正文及支持关键结论所需的附录，不把下载成功或只读摘要写成全文精读。

实验选择能支持机制的比较与消融，交代数据、人群、基准、指标定义/单位、设置和原文表图；区分作者报告、本仓库复现、分析与假设。不凭离线数字推导线上收益。章节随具体技术命名，[论文提纲](../文档/模板/论文笔记模板.md)只作提示，不要求填满栏目，也不复制整篇译文。文末集中链接原文/版本、中文产物、译后主文件和相关问题，简记实际阅读/翻译范围与缺口。

实际阅读范围确定后，按[工具说明](../scripts/README.md)用 `register` 登记原件与版本，取得来源指纹并运行 `plan`；已登记的资料只在原件、版本或阅读范围确有变化时更新。若先登记收件，阅读范围必须写当时事实。

### 5. 将解法合并进问题与模块

先确定这篇论文具体解决哪些问题，再读取对应问题页。把可复用的机制、必要公式、适用条件、代价和局限写进正文，关键论述链接论文阅读笔记并定位原文章节/表图；保留旧来源独有的条件与结论。一篇论文可贡献多个问题，同一解法可对应多篇论文。

已有方案时围绕困难、核心假设、监督/数据需求、训练与推理、成本和证据作比较，说明“相同在哪里、改了哪一步、何时选用”。不同协议的数字不直接排名。论文内部基线/消融可用于比较，但明确依据来自本篇；Related Work 中的转述不冒充独立精读。无可靠对照时先写单方案，不设空比较表；有实质缺口再定向补查。

维护问题页 `module`、`solutions`、来源指纹与必要的 `related`，论文阅读笔记反链问题页；字段见 [SCHEMA](../SCHEMA.md)，写法见[问题提纲](../文档/模板/问题模块模板.md)。只有可独立复用且已有足够内容时才拆 concept/method 页，不机械生成“一篇论文一个方法页”。未解冲突保留并记入[审核台](审核台.md)，不为了完成收据改为 reviewed。

### 6. 检索、验证与交付

自查所有受影响陈述、数字、原文定位与版本；再对引用该来源且已自查的页面执行 `integrate`，记录实际检查和限制。随后 `index` 生成知识地图与来源反向引用，不手填第二份目录。用论文名/方法名和问题关键词分别检索一次，确认两条路径均能到达“问题 ↔ 论文笔记”，从知识地图可按模块进入。

按[正文约定](../SCHEMA.md#正文写法)检查引用的阅读体验：关键公式及符号在本页完整可读，深入解释链接精读小节，原文核对链接已核实的固定版本 PDF 页码或 HTML 锚点。不能把摘要页伪装成公式直达入口；手工核实页码与目标小节，链接检查器通过不代表定位正确。

```bash
python3 scripts/wiki.py plan
python3 scripts/wiki.py index --check
python3 scripts/wiki.py lint
python3 scripts/translations.py check
python3 scripts/pdf_releases.py check
python3 scripts/check_context.py
git diff --check
```

`plan` 中本篇相关的待整合项须处理或说明真实缺口；warning 逐项判断，不为消除孤页提示编造关联。恢复环境缺原件时说明 `--local` 的限制。追加一条 [log](../log.md)，核查实际 diff，只暂存本任务文件并执行 `git diff --cached --check`，完成中文本地提交。命令通过不等于语义、翻译或科研结论正确；默认是当前 Agent 自查。

完整交付应包含：可用译文与实际格式/范围，PDF 的许可记录、实际私有备份/登录下载状态与未完成原因；有源码时可编辑的译后工程；能独立学习的精读；已归入模块的问题与方案比较；可相互检索的引用；实际检查结果及本地提交。有缺项就明确保留，不能笼统称全部完成。用户通常只需收到译文、精读、问题页链接及简短结果，不复述维护过程。

### 产物固定落位，按需生成

| 产物 | 位置与用途 |
|---|---|
| 原始 PDF、下载后未修改的 LaTeX | `.local/papers/<ID>/original/`，源码可放 `original/latex/`，便于直接查阅 |
| 登记原件的不可变快照 | `.local/sources/<ID>/<sha256>/`；哈希与版本见 `来源/<ID>/来源.json` |
| 正式 Markdown 译文 | `译文/<ID>/中文译文.md`，逐篇许可确认后入 Git；元数据与自动目录在 `译文/` |
| 中文 PDF、工作版/未授权 Markdown | `.local/papers/<ID>/translation/`，本地附件 |
| 译后 LaTeX、样式、图与参考文献 | `.local/papers/<ID>/translation/translated-sources/`；保留可编辑工程 |
| 渲染检查与编译诊断 | `.local/papers/<ID>/qa/`，有实际产物再保存，不强制额外 QA 报告或逐阶段状态文件 |
| 单篇精读 | `来源/<ID>/阅读笔记.md`，唯一主要解读正文，入 Git |
| 可复用知识与多方案比较 | `知识库/` 对应问题页，入 Git；自动入口为 `知识库/知识地图.md`、`来源/来源目录.md` |

上述本地附件不入 Git。原文与中文PDF统一私有备份；LaTeX、其他来源快照和运行产物另做备份，不能声称已随PDF上传。恢复原文时校验来源卡原哈希；哈希不能替代原件。公开链接使用固定版本原文，附件路径用行内代码标明不随 Git 分发。PR 与普通克隆不要求本地原件；持有完整快照的维护者可额外执行 `lint --local`。GitHub 共建按 [贡献指南](../CONTRIBUTING.md) 执行。每篇通常只新增来源卡和一份阅读笔记、更新少量问题页及自动索引。常规论文不新增 TODO/交接，不改整套根上下文；不自动下载大数据、运行模型或扩展为全领域综述。普通问答和后续资料继续按下文合并知识。

## 按模块学习

从 [知识地图](../知识库/知识地图.md) 选择模块，先看“问题 → 解决方案 → 核心思路 → 对应论文”，再进入问题页比较、论文阅读笔记精读。用户问“这个模块有哪些问题/方法”时，按此顺序回答，区分库内已读与待补资料；不要用任务交接代替知识内容。

尚无精读论文的问题从模块导读看职责、问题和解法族，阅读线索查 [候选表](../知识库/阅读/候选论文.md)。同一模块同时容纳传统与生成式解法；生成式的跨模块关系见 [专题](../知识库/总览/生成式推荐专题.md)。正式问题页形成后，把导读中的对应问题链接到它，保留一份主要比较正文。

## 摄入与更新

1. 搜索 [知识地图](../知识库/知识地图.md)、来源标题/URL、别名和正文；同一资料继续原来源 ID，同一知识对象优先合并。先读来源，再决定知识落点。
2. 获取需要阅读的原件，固定论文版本、代码 commit 或本地 skill 哈希。用 `register` 登记快照；此动作仅表示收到资料。阅读范围如“全文”必须真实，部分阅读列章节/符号。
3. 写 `来源/<ID>/阅读笔记.md`：核心理解、证据定位、未读部分、局限与候选影响。运行 `plan` 查看当前版本与旧知识的差异。
4. 列出新增事实、旧结论的补充/替代/冲突、直接受影响页与关联候选。读取这些页，合并保留旧来源独有的条件；必要时建立一个稳定新页。
5. 自查关键陈述、数字与定位；来源当前版本写入页面 `sources`。未解决的实质矛盾标 contested 并登记 [审核台](审核台.md)，不能为了清空队列改为 reviewed。
6. 对自查完成且引用该来源的所有页面执行 `integrate`，写具体自查说明。draft/contested 可留待整合；不要伪造收据。此处不要求额外用户批准，用户参与按任务需要。
7. `index` 更新知识与来源目录；路由发生变化才更新 [上下文路由](上下文路由.md)。追加 [log](../log.md)，运行 lint、上下文检查和相关代码验收，检查 diff 后本地提交。

多文件语义更新是一轮工作单元；工具只对单个 JSON 原子写入，不提供多文件数据库事务或并发锁。中断后运行 plan、lint，核对 Git diff，继续未完成项。

## 问答促进知识生长

1. 按问题选择上下文包、检索知识页，读取原文需要的最小集合；缺证时回到来源或做只读补查。
2. 引用页面/来源回答，区分作者报告、本地复现、分析和假设；报告冲突和适用条件。
3. 只有产生可复用的新连接、比较、纠错、实验结论时才回写知识。用已有来源的推断写明推理，不把聊天回答另登记为外部证据。
4. 新推断优先并入已有页面；必要的新页登记 sources 与 related、同步 index 和 log。若改动来源笔记或协议，plan 会提示重新自查。

## 检查促进知识生长

结构检查运行 `lint`，来源变更运行 `plan`。Agent 语义复核检查：是否曲解原文、同指标异口径、条件遗漏、循环引用、过时主张和真实知识缺口。

可当场验证的错误直接改；需新证据/实验的事项登记审核台，写影响范围与解除条件。审核台是知识问题，不是自动执行任务表；进入实施时再登记 TODO。审核后只将确认的增量写入正文和 log。

## 冲突与来源升级

新旧陈述按任务、人群、数据、版本、指标和资源对齐。可以同条件替代则保留简短更正理由；不同条件并存则分别列适用范围；无法判定保留冲突。来源更新后，plan 的 affected 是直接引用页，review_candidates 是一跳关联候选，不是已经证实失效的结论。

不因来源删除自动擦除整页，也不因 sources 数组还在就认定旧贡献已保留。对照 Git diff 检查正文。撤回与恢复细节见 SCHEMA。
