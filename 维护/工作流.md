# 维护工作流

[知识契约](../SCHEMA.md) 定义字段与证据；本页是唯一操作流程。常规论文和问答直接处理，只有跨会话中断、并发、系统改造或实验才登记 [任务队列](../TODO.md)，不为每篇论文重写根上下文。

## 论文知识沉淀标准流程

用户提供 URL、arXiv ID、PDF 或题名，即默认执行 **核实原文 → 翻译 → 精读 → 按问题提炼与比较 → 全库反查与原文纠偏 → 检索验收 → 提交并同步两库**。这是后续论文的统一做法，实际范例见 [ESMM 精读](../来源/SRC-ESMM/阅读笔记.md)与[问题页](../知识库/问题/点击后转化率估计.md)，首次执行证据见 [R001](../文档/会话/R001.md)。已有产物增量补齐；模块归属由 Agent 判断，身份唯一且原文可取得时直接推进。用户明确只需其中一步时遵从。

### 1. 定位论文与已有知识

核实题名、作者、年份、arXiv/DOI、实际采用的版本和检索日期。先检索来源题名/标识、问题关键词、方法名及别名，读取最相关的阅读笔记和问题页。同一论文沿用来源 ID，同一问题优先合并；新版保留旧版本，不重建平行来源。题名不能唯一定位时才澄清身份。

### 2. 取得原件与可编辑源码

获取固定版本的原始 PDF；有 arXiv 版本时，按 `arxiv-translator` 的顺序获取 LaTeX 源码、定位主文件和实际参与编译的子文件。**取得源码后先保留未修改副本，再在副本上翻译**；哈希冻结的是证据原件，译后源码持续可编辑。

以正式 PDF 确认出版正文范围。源码中的注释旧稿、模板示例、未发表实验不算论文内容；检查附录是否属于采用版本。优先保存上游原始压缩包；只有解压文件时可打包留存，但来源卡必须注明“下载后未修改文件的本地重新打包”，不能声称是上游压缩包原字节。LaTeX 是排版源码，不等于算法实现代码；有必要查官方实现时另固定 commit 与实际阅读范围。

### 3. 翻译、编译与原文核对

有 LaTeX 时执行 `arxiv-translator` 的确定 ID、下载源码、当前模型翻译与扫描、编译四步。翻译正文、摘要、图表标题、描述性脚注和代码注释；公式、代码本体、引用标签、图片路径和专名按 skill 保留。默认附录保留原文，用户要求全文时再翻附录；图内英文未重绘等范围在阅读笔记文末说明。原文疑似错误保留并加译注，不悄悄改写。

扫描后逐项处理残留，检查所有实际编译子文件；主文件的 `body` 扫描可能漏掉无文档边界的子文件，需补充扫描或人工核对。**中文PDF是默认交付项，首次失败不是结束翻译阶段的条件。** 编译按以下顺序推进，具体诊断、命令与已验证案例见[中文PDF编译与验收](../文档/工具/中文PDF编译与验收.md)：

1. 按 skill 调用编译并遵守同一服务/配置的重试上限，保存控制台和TeX日志。远程超时先归为该链路受阻，不能直接判定原稿或模板无法编译；重复请求前要有具体修复或新证据。
2. 远程受阻后探测已有本地运行库，包括默认PATH之外的TeX Live/MacTeX和受管缓存；核对实际可用locale、引擎与中文字体，用含中文及公式的最小文档验证。`command -v`未命中或`--version`成功均不足以判断完整编译能力。
3. 保留完整译后正文和资源，在副本上修复启动环境、宏包、字体及参考文献工具链；必要时切换LuaLaTeX/XeLaTeX与配套CJK栈，再编译原排版。每次引擎切换均重新验收中文字体显示与提取。
4. 原模板仍受阻时，使用已有工具将**同一份正文译文**重排为中文PDF，保留章节、公式、表格、图与引用，注明排版变化和真实缺项。无LaTeX时也从正式PDF翻译后尝试重排；不得改成摘要或精读PDF来充当论文译文。
5. 导出PDF到固定本地附件路径后才进入PDF验收；只有编译诊断成功、预览标签或内存中的产物时继续完成导出。仍受阻则记录已尝试链路、具体错误、保留工程和下一条可执行动作；已知且可修复的环境问题继续处理，不等待用户再次要求重试。

核对关键公式/符号、表格数值与单位、图表/文献引用；渲染最终 PDF 并逐页目视检查中文缺字、裁切、图表可读性、公式、引用和出版年份。修订后重新检查受影响内容与最终 PDF。保留可继续编译的译后源码、图片及必要样式/参考文献；临时目录只在有效产物已保存后清理。已有工具不足时说明具体限制，不为一次翻译擅自安装庞大环境。

正式 Markdown 译文公开前按 [许可规则](../LICENSE) 核实该固定版本允许翻译再分发，写入 `译文/<ID>/中文译文.md`，并在 `译文/目录.json` 登记作者、原文版本、许可核实入口/日期、翻译范围、修改说明与 SHA256。未确认公开授权的全文译文不公开，按当前范围保留本地或私有备份；不把 arXiv 非独占分发许可当作公众翻译许可。

原文 PDF 取得并登记后，以及中文 PDF 完成核查后，按[PDF私有维护流程](../文档/工具/中文PDF发布.md)备份到独立私有附件库。原文保留原字节与来源快照哈希；不同版本、未核实镜像和译文分开登记，保留原作者署名及权利声明。译文仍核查固定版本的许可，但私有存储决定不等于公开翻译授权。上传前核对私有可见性、版本/范围/隐私，上传后用有权账号实际下载核验大小与SHA256；成功后才登记已私有备份。后续同类附件及配套目录更新已获持续授权，公开PDF发布授权已被本规则替代，不自动邀请账号或扩大访问。公开库只更新许可/范围盘点与访问说明，笔记保留公开原文入口并链接PDF访问说明；不提供需登录的逐篇链接作为公开下载。Markdown与PDF分别登记。

无 LaTeX 时明确该 skill 无法完成源码翻译，改用可读取的 PDF，保存按原文章节与页码可核对的中文 Markdown，并执行上述正文重排与验收。只有已检查适用编译/重排路径仍存在真实阻塞，或用户明确缩小范围时，才交付PDF缺项；将错误证据、已做尝试与恢复动作简记在阅读笔记，不宣称全流程完成。译文遇阻仍继续可做的原文精读和归纳，关键事实回查原文。

### 4. 保存一篇可独立学习的技术精读

先选出原文承担主线的关键架构/训练/推理及实验图，按[原图交付规则](图片资源规范.md#作者原图的默认交付)直接嵌入主笔记对应讲解，这是默认必交项；需要时再加自绘示意补充。两类图共用 `资源/图片/`，其他文档与知识页统一引用同一物理文件，不设许可前置门槛或另生成阅读版；“PDF已有图”不算笔记原图交付。

写入 <code>来源/&lt;ID&gt;/阅读笔记.md</code>，按[精读写作与验收](论文精读写作与验收.md)执行：先定位内容的奠基/沿用/改进角色，再用贯穿实例讲通输入、信息流、输出、监督和使用；公共知识保留本篇轻解释并链接唯一详解，承重图片按[单实体规范](图片资源规范.md)嵌入。经典方法的过程与失败位置要先于改进；不能靠后续几十次基础追问补齐主线。

正文按连贯技术文章写，标题随内容命名，[论文提纲](../文档/模板/论文笔记模板.md)只作提示。阅读支持关键结论所需的正文/附录，实验用于检验机制并保留条件和例外。起草及修订分步CR，最后完成技术证据与读者路径两轮自查、修复后再验收；不以字数、关键词或自动lint判断教学充分。文末集中链接原文、版本和实际产物，简记阅读/翻译范围与缺口。

实际阅读范围确定后，按[工具说明](../scripts/README.md)用 `register` 登记原件与版本，取得来源指纹并运行 `plan`；已登记的资料只在原件、版本或阅读范围确有变化时更新。若先登记收件，阅读范围必须写当时事实。

### 5. 将解法合并进问题与模块

先确定这篇论文具体解决哪些问题，再读取对应问题页。把可复用的机制、必要公式、适用条件、代价和局限写进正文，关键论述链接论文阅读笔记并定位原文章节/表图；保留旧来源独有的条件与结论。一篇论文可贡献多个问题，同一解法可对应多篇论文。

已有方案时围绕困难、核心假设、监督/数据需求、训练与推理、成本和证据作比较，说明“相同在哪里、改了哪一步、何时选用”。不同协议的数字不直接排名。论文内部基线/消融可用于比较，但明确依据来自本篇；Related Work 中的转述不冒充独立精读。无可靠对照时先写单方案，不设空比较表；有实质缺口再定向补查。

维护问题页 `module`、`solutions`、来源指纹与必要的 `related`，论文阅读笔记反链问题页；字段见 [SCHEMA](../SCHEMA.md)，写法见[问题提纲](../文档/模板/问题模块模板.md)。只有可独立复用且已有足够内容时才拆 concept/method 页，不机械生成“一篇论文一个方法页”。未解冲突保留并记入[审核台](审核台.md)，不为了完成收据改为 reviewed。

### 6. 全库反查、检索验证与交付

译文、精读和问题页已更新后，以本轮论文、精读笔记与新增结论为起点，反查整个知识库。单篇与批次都执行这一轮。批次汇总各篇交叉影响后一起复核。

1. 用 `plan` 查来源绑定和待整合页，用 `python3 scripts/wiki.py review-scope SRC-... --term 方法别名` 查知识库全域的正文提及、论文笔记回链、关联页和其他论文笔记。用题名、版本、方法别名、问题关键词和关键结论补搜未命中的说法，沿总览、模块、问题、候选书目、阅读路线与来源目录核对跨模块入口。检索结果是复核线索，按实际涉及的任务与陈述读页，记录查过的范围。
2. 核对本轮论文解法所涉及的问题是否已有覆盖。逐项比较问题定义、机制、已有方法、适用条件、证据和反例，发现缺项就优先补入唯一知识正文，确有独立问题时再新建。判断相关页是否需要修订正文、补回链、更新来源版本与索引。缺证的方向保留具体待查问题，交代它影响哪条结论或哪条阅读路径。
3. 发现疑似错误、过时判断或不一致时，先回到双方固定版本原文的正文、公式、图表、附录或官方勘误。逐项对齐假设、任务、人群、数据切分、基准、指标单位、汇总方式与版本。能裁定则按原文同步修正论文笔记、问题页及传播了同一说法的其他页，并留下更正证据。不同条件下均成立的结论标明各自条件。原文自己矛盾、证据不足或无法获取时，在涉及页面与[审核台](审核台.md)写清分歧、已查位置、影响和解除条件，有争议的判断保持待核。
4. 修订后再反查受影响陈述、来源绑定和阅读路径。对已完成语义自查的直接引用页执行 `integrate`，收据写清覆盖范围、实际更新和仍未决的问题。随后运行 `index` 生成知识地图与来源回链。分开以完整题名或来源 ID、方法别名、问题关键词实际检索，核对模块入口和“问题 ↔ 论文笔记”双向链接。没有知识或索引增量时记录本轮复核范围与结论。

按[正文约定](../SCHEMA.md#正文写法)检查引用的阅读体验：关键公式及符号在本页完整可读，深入解释链接精读小节，原文核对链接已核实的固定版本 PDF 页码或 HTML 锚点。不能把摘要页伪装成公式直达入口；手工核实页码与目标小节，链接检查器通过不代表定位正确。

```bash
python3 scripts/wiki.py plan
python3 scripts/wiki.py index --check
python3 scripts/wiki.py lint
python3 scripts/translations.py check
python3 scripts/pdf_releases.py check
python3 scripts/check_context.py
git diff --check
```

`plan` 中本篇相关的待整合项须处理或说明真实缺口；warning 逐项判断，不为消除孤页提示编造关联。恢复环境缺原件时说明 `--local` 的限制。追加一条 [log](../log.md)，核查实际 diff，只暂存本任务文件并执行 `git diff --cached --check`，完成中文本地提交。命令通过不等于语义、翻译或科研结论正确；默认是当前 Agent 自查。

完整交付应包含：覆盖约定正文的中文PDF与实际翻译范围，PDF 的许可记录、实际私有备份/登录下载状态与未完成原因；有源码时可编辑的译后工程；能独立学习的精读；已归入模块的问题与方案比较；可相互检索的引用；实际检查结果、两库提交及远端核验结果。收尾先核对PDF实际存在且可解析、章节范围匹配、最终页数/哈希已记录、逐页渲染目视完成、中文可提取且引用可用；这些检查通过前不写“论文流程完成”。编译诊断成功、Markdown存在、结构lint通过或摘要PDF存在均不能替代上述核对。

本地PDF验收后，须接着执行[私有维护流程](../文档/工具/中文PDF发布.md)：上传采用的原文与中文PDF，核对远端digest，真实登录下载核验并自动清理核验下载，再同步私有完整账本及公开盘点。每篇本地和私有 Releases 各保留一份当前采用原文和一份正式中文 PDF，版本切换和恢复按[单正式版维护](../文档/工具/中文PDF发布.md#单正式版与替换顺序)执行。该范围已有持续授权，不等用户再次要求；公开译文许可未确认不等于私有备份未授权。“本轮仅重试编译”也不自动免除恢复后的备份步骤。只有实际访问、网络或完整性阻塞，或用户明确缩小为仅本地交付时，才保留local-only，写明具体证据和恢复动作。确有缺项时只交付已完成部分，明确未完成原因；本地生成、视觉验收和私有备份分别报告。

自 2026-11-23 起，每次单篇或批次完成验收后，按持续授权提交并推送两库的当轮增量。将两库远端核验纳入本轮完成条件。私有附件库 Lsiming/recsys-knowledge-attachments 在认证下载后提交并推送附件目录增量，核对正式资产与账本。公开主项目 Lsiming/recsys-knowledge 提交已验收的精读、知识、来源与盘点增量，并按 [GitHub API 推送流程](../文档/工具/GitHub共建.md#通过github-api推送)同步 main。两库分别核对发布范围、远端基线、本地和远端 SHA 及对应 CI。某库无本轮增量时核对其远端状态即可。交付时记录实际提交及验证结果，若远端访问或 CI 受阻则记录具体阻塞与恢复动作。用户明确只要求某一步或仅本地时，按本轮要求交付。

会话交付中文PDF时，先验证当前采用版本的本地文件存在、可解析且与版本记录的哈希一致；缺失或不一致时，保留现有字节，从已登记私有备份登录下载、核对完整哈希后原子恢复到唯一正式位置。替换前的独有字节先判明是哪一版，保护仍被引用的证据。确认后给该实际文件的可点击链接；PDF访问说明、目录页和行内代码路径不能代替文件交付。公开正文仍只链接访问说明并标明“私有备份下载说明”，本地附件位置按契约用行内代码；不要把说明页标成PDF文件直达。用户通常只需收到译文、精读、问题页链接及简短结果，不复述维护过程。

### 产物固定落位，按需生成

| 产物 | 位置与用途 |
|---|---|
| 采用版原始 PDF | `.local/sources/<ID>/<sha256>/<原文件名>` 保留原字节，原有阅读入口可使用指向该文件的相对符号链接 |
| 下载后未修改的 LaTeX | `.local/papers/<ID>/original/`，源码可放 `original/latex/` |
| 登记原件的不可变快照 | `.local/sources/<ID>/<sha256>/`；哈希与版本见 `来源/<ID>/来源.json` |
| 正式 Markdown 译文 | `译文/<ID>/中文译文.md`，逐篇许可确认后入 Git；元数据与自动目录在 `译文/` |
| 正式中文 PDF、工作版/未授权 Markdown | `.local/papers/<ID>/translation/`。每篇只保留一份正式中文 PDF，优先维持已有正式路径 |
| 译后 LaTeX、样式、图与参考文献 | `.local/papers/<ID>/translation/translated-sources/`；保留可编辑工程 |
| 渲染检查与编译诊断 | `.local/papers/<ID>/qa/`，有实际产物再保存，不强制额外 QA 报告或逐阶段状态文件 |
| 论文学习思考 | `来源/<ID>/学习思考.md`，有实际疑问时创建，短答与精确章节导航 |
| 单篇精读 | `来源/<ID>/阅读笔记.md`，唯一主要解读正文，入 Git |
| 可复用知识与多方案比较 | `知识库/` 对应问题页，入 Git；自动入口为 `知识库/知识地图.md`、`来源/来源目录.md` |

上述本地附件不入 Git。原文与中文PDF统一私有备份；LaTeX、其他来源快照和运行产物另做备份，不能声称已随PDF上传。恢复原文时校验来源卡原哈希；哈希不能替代原件。公开链接使用固定版本原文，附件路径用行内代码标明不随 Git 分发。PR 与普通克隆不要求本地原件；持有完整快照的维护者可额外执行 `lint --local`。GitHub 共建按 [贡献指南](../CONTRIBUTING.md) 执行。每篇通常只新增来源卡和一份阅读笔记、更新少量问题页及自动索引。常规论文不新增 TODO/交接，不改整套根上下文；不自动下载大数据、运行模型或扩展为全领域综述。已有论文的后续问题按[学习思考整理](#论文疑问与学习思考整理)增量处理；普通问答和后续资料继续按下文合并知识。

## 论文疑问与学习思考整理

已经读过的论文，后续学习统一走 **新疑问先留在论文思考页 → 核对论文与已有正文 → 在合适位置补充解答 → 把精确链接补回思考页**。这是增量学习，不因再次提问重跑翻译或复制整套资料。实例见[GPT初代学习思考](../来源/SRC-GPT1/学习思考.md)。

### 两种日常入口

| 场景 | 用户怎样调用 | 整理时保留什么 |
|---|---|---|
| 手机学习后，把与其他AI交流的问题批量带回 | “按论文疑问整理流程，整理这批GPT问题。”附问题清单、必要对话摘录或文件即可 | 原问题、限定条件、卡住的例子/公式；已有回答作为待核对理解，不直接当证据 |
| 直接在当前会话讨论，聊完一段后沉淀 | “把本会话刚才关于GPT的疑问和思考，按论文疑问整理流程沉淀。”也可指定某段讨论或主题 | 从当前可见对话提取用户实际疑问、递进追问、理解变化和已讨论答案；只整理尚未沉淀的增量 |

日常交流可以先充分讨论，用户调用整理时再执行闭环。输入无需预先改成固定表格，也无需提供目录、任务号或元数据。两种入口可混合：同一论文的清单与当前讨论一起去重；一批涉及多篇论文时，按已有来源分别落位，共用原理仍指向同一知识正文。只有论文身份或关键语境无法合理判断、且会影响答案时才追问；其他缺证可保留为具体未解问题。

当前会话只使用真实可读的上下文，不声称已读其他AI或其他会话的完整聊天。跨会话材料由用户提供，或在明确指定且实际可读取时检索。问题来源简记“外部交流整理”或“本会话讨论”及日期；原始对话按需本地保留，不将整段聊天、私人信息或会话标识复制进公开正文。AI提出的延伸问题与用户实际追问区分，不能替用户编造疑问或“已掌握”的结论。

### 先归并问题，再补实际答案

1. **定位并留下本轮问题。** 检索已有来源与思考页，沿用论文ID。在同一论文思考页先写入疑问与必要语境，再逐项处理；首次有实际问题时创建该页。少量问题直接融入已有分组，不为一次导入另建平行页。
2. **按疑问含义去重。** 相同疑问合并到原条目，保留改变答案的条件、例子和递进追问；“是什么”“为什么”“梯度怎样走”不能仅因关键词相同而删掉。已有解答足够时复用；新条件补原条目或相邻小节。重复调用不生成同一份问题副本。
3. **核对原文和已有解答。** 检索论文笔记、知识正文及固定版本论文/官方代码。检查问题前提，区分原文结论、实现、数学推导与分析；外部AI和本会话的回答按同一标准核对。有实质缺口再定向补查，不默认扩成领域综述。
4. **在合适位置直接补答。** 本篇任务、结构、实验和代码细节留论文笔记；可复用概念、公式和比较合并已有知识正文，足够独立才建页。思考页留短答、关键误区和深入链接，不另存“建议补充”清单，不两处复制完整推导。证据不足时写清具体缺口和可回答部分，不把猜测写成已解决。
5. **回填章节直达与回链。** 每个归并问题至少链接到真正回答它的标题锚点；必要时分别链接论文细节与通用原理。公式/例子在目标正文，不能只回链到整篇目录。论文笔记顶部链接思考页，知识正文在有学习意义处回到论文或思考分组。
6. **CR后完成本轮沉淀。** 对照原输入检查所有问题与追问的落点，核查前提、推导、证据、目标实际内容及锚点。重复整理只更新增量；无新知识时复用解答。仅修改问题/入口无需重登记论文；实质正文或来源增量按摄入规则运行plan、整合自查与索引，追加log并本地提交。仅问题导航变化也检查链接、更新存在的索引入口并本地提交；没有任何新增或修正时不作空提交。多步任务每步CR，最后全局CR与修复；维护记录不混入学习正文。

### 一篇论文的阅读入口与资料归属

以“论文资料聚合、知识正文复用”组织：`来源/<ID>/阅读笔记.md`是主要入口，顶部聚合固定原文、中文PDF位置章节、私有备份下载说明、按需存在的思考页和关键知识章节；链接文字明确区分文件位置与下载说明。`来源/<ID>/学习思考.md`收本论文疑问、追问、短答与章节链接，无问题不机械建空页。[轻量提纲](../文档/模板/论文学习思考模板.md)可按内容删改。

原件快照、可编辑译后工程、中文PDF与私有备份沿用上表位置，由入口串在一起，不搬动或复制既有附件。抽象原理只在知识库维护一份主要正文；同一个疑问从多篇论文遇到时，各自保留语境并链接同一原理解答。方案比较进入已有问题页，个人学习中的每个小疑问不机械新建problem页。

## 按模块学习

已知业务问题时，从[场景导航](../知识库/知识地图.md#按场景找问题)选搜索、推荐、营销或通用方法。按技术模块学习时，进入[模块目录](../知识库/知识地图.md#按模块学习)，先看“问题 → 解决方案 → 核心思路 → 对应论文”，再进入问题页比较、论文阅读笔记精读。用户问“这个模块有哪些问题/方法”时，按此顺序回答，区分库内已读与待补资料；不要用任务交接代替知识内容。

尚无精读论文的问题从模块导读看职责、问题和解法族，阅读线索查 [候选表](../知识库/阅读/候选论文.md)。同一模块同时容纳传统与生成式解法；生成式的跨模块关系见 [专题](../知识库/总览/生成式推荐专题.md)。正式问题页形成后，把导读中的对应问题链接到它，保留一份主要比较正文。

## 摄入与更新

1. 搜索 [知识地图](../知识库/知识地图.md)、来源标题/URL、别名和正文；同一资料继续原来源 ID，同一知识对象优先合并。先读来源，再决定知识落点。
2. 获取需要阅读的原件，固定论文版本、代码 commit 或本地 skill 哈希。用 `register` 登记快照；此动作仅表示收到资料。阅读范围如“全文”必须真实，部分阅读列章节/符号。
3. 写 `来源/<ID>/阅读笔记.md`：核心理解、证据定位、未读部分、局限与候选影响。运行 `plan` 查看当前版本与旧知识的差异。
4. 列出新增事实、旧结论的补充/替代/冲突、直接受影响页与关联候选。读取这些页，合并保留旧来源独有的条件；必要时建立一个稳定新页。
5. 自查关键陈述、数字与定位；来源当前版本写入页面 `sources`。未解决的实质矛盾标 contested 并登记 [审核台](审核台.md)，不能为了清空队列改为 reviewed。
6. 对自查完成且引用该来源的所有页面执行 `integrate`，写具体自查说明。draft/contested 可留待整合；不要伪造收据。此处不要求额外用户批准，用户参与按任务需要。
7. `index` 更新知识与来源目录；路由发生变化才更新 [上下文路由](上下文路由.md)。追加 [log](../log.md)，运行 lint、上下文检查和相关代码验收，检查 diff 后本地提交。

多文件语义更新是一轮工作单元；工具只对单个 JSON 原子写入，不提供多文件数据库事务或并发锁。中断后运行 plan、lint，核对 Git diff，继续未完成项。

## 问答促进知识生长

1. 按问题选择上下文包、检索知识页，读取原文需要的最小集合；缺证时回到来源或做只读补查。
2. 引用页面/来源回答，区分作者报告、本地复现、分析和假设；报告冲突和适用条件。
3. 只有产生可复用的新连接、比较、纠错、实验结论时才回写知识。用已有来源的推断写明推理，不把聊天回答另登记为外部证据。
4. 新推断优先并入已有页面；必要的新页登记 sources 与 related、同步 index 和 log。若改动来源笔记或协议，plan 会提示重新自查。

## 检查促进知识生长

结构检查运行 `lint`，来源变更运行 `plan`。Agent 语义复核检查：是否曲解原文、同指标异口径、条件遗漏、循环引用、过时主张和真实知识缺口。

可当场验证的错误直接改；需新证据/实验的事项登记审核台，写影响范围与解除条件。审核台是知识问题，不是自动执行任务表；进入实施时再登记 TODO。审核后只将确认的增量写入正文和 log。

## 冲突与来源升级

新旧陈述按任务、人群、数据、版本、指标和资源对齐。可以同条件替代则保留简短更正理由；不同条件并存则分别列适用范围；无法判定保留冲突。来源更新后，plan 的 affected 是直接引用页，review_candidates 是一跳关联候选，不是已经证实失效的结论。

不因来源删除自动擦除整页，也不因 sources 数组还在就认定旧贡献已保留。对照 Git diff 检查正文。撤回与恢复细节见 SCHEMA。

## 验收后的本地产物清理

验收即清理。保留唯一采用版原文、唯一正式中文 PDF、来源卡及可编辑译后工程的必要输入。核验下载使用[私有验证命令](../文档/工具/中文PDF发布.md#登录下载)，临时文件成功、失败或超时均自动清理，只登记哈希、页数、大小、日期及结果。原件的已有阅览路径可用相对符号链接维护。任务完成后清理逐页渲染与预览、可再提取文本、编译辅助文件、失败下载、一次性改写/上传脚本和已固化来源的调研缓存；日志只保留仍用于解释真实故障的必要部分。译后工程中的图表PDF和参考文献输入不能当成成品重复件删除。

清理既有副本时先核对正式文件的完整 SHA-256 与登记，按已验收记录识别同版本清理前后或被替代的构建。确认的旧成品、上传暂存和核验副本退出附件目录。历史版本身份、适用范围及哈希保留在来源卡和 Git。无法确认归属的独有资料以及 TeX 实际引用的图表和输入单独保留，按其用途核查。

临时目录不能整树按名字删除：先核对其中是否有原件、官方代码、译后工程或未整合用户文件。已提交旧稿使用Git恢复入口，仍被引用的核验表保留；清理后同步引用并验证受保护文件哈希。删除统计、实际保留理由和验证结果只写对应任务交接与一条log，不另造逐文件公开报告。普通论文仍不强制独立任务或QA报告。
